THE DIAGNOSIS (measured before this declaration; the probe and its outputs are in diagnosis/ and are part of this
evidence, the numbers the code commit states)
- ORIGIN. tycho fc568fe7 (2026-03-15, "separate MKL Pardiso init time from PSIOPT timing"): on Windows the first
  pardiso() in a process carried ~100 ms of runtime initialization (thread pool, CPU dispatch, allocators) inside
  Analysis/Reorder time; dsecnd() was added once per process before the solver's timer to pay it there, reported as
  "MKL Initialization". It came to hven verbatim with the engine move (b36d24a9) and became
  ensure_solver_initialized() / solver_initialization_seconds / kSolverInitialized.
- WHAT dsecnd() ACTUALLY DOES ON THIS BOX. Its first call calibrates MKL's clock by spinning on time() to a wall-second
  boundary (perf: difftime, mkl_serv_get_clocks_frequency, __vdso_time): 0.17-0.98 s and up to ~3.85e9 user
  instructions per process, depending on where in the second the process starts.
- IT WARMS NOTHING PARDISO USES. diagnosis/mkl_probe.c (MKL linked as hven links it), first pardiso() phase 13 on a 5x5
  symmetric indefinite matrix, 3 rounds (mkl_probe.txt): cold 2.26-2.51 ms; after dsecnd() 2.29-2.32 ms; after
  mkl_get_version() 2.24-2.36 ms; after mkl_get_max_threads() 0.30-0.31 ms (the call itself 1.97-2.01 ms). A dsecnd()
  AFTER two pardiso() calls still spins (~0.97 s) unless one was made before: Pardiso never triggers the calibration,
  so removing the call does not move the spin into the solve.
- THE REPLACEMENT. mkl_get_max_threads() (oneMKL Developer Reference, Support Functions / Threading Control; declared
  in mkl_service.h) brings up the threading layer (the OpenMP runtime) -- the first-call cost the original commit
  meant to move out of the timed phases -- at no instruction cost: 6.08e6 instructions:u per probe process with or
  without it, 5 rounds (mkl_probe_nolate.txt). Chosen over (a) plain removal, which would leave that bring-up inside
  the first factorization and make solver_initialization_seconds always 0 on MKL, and (b) an opt-in, which would keep
  a known-useless 1 s spin available behind a switch. Accelerate's branch (ensure_accelerate_initialized) is untouched.
  Windows runs the same MKL branch: UNOBSERVED there.
- OTHER TIMING CALLS. MKL's dsecnd()/second() have no other caller in src/, include/, bench/, bindings/, examples/ or tests/;
  the IPM's timers are std::chrono::steady_clock (detail::Timer). MKL's own Pardiso timer (mkl_pds_lp64_timer_pardiso)
  appears with 1-2 samples in both arms and never reaches mkl_serv_get_clocks_frequency. Pardiso msglvl is 0.
- CONSUMERS of solver_initialization_seconds / kSolverInitialized / solver_init_time_s: the IPM driver
  (ipm_solver.cpp), the console sink (prints the notice when > 0.5 ms: still printed, ~1.5 ms), the JSON trace writer,
  enum_names, tests that only warm the process-once event away (test_ipm_trace, test_console_sink, test_trace_writer,
  test_callback, test_warm_protocol), docs (trace-schema-v0.md, concurrency.md). None asserts a value; bench/,
