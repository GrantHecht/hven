4. MISATTRIBUTION THE FROZEN BUCKET MAP CANNOT SEE: the process-once OpenMP runtime initialization.
   - **Cause (gdb, results/init-audit.txt).** F1's ensure_solver_initialized() calls mkl_get_max_threads().
     The call chain continues: mkl_serv_domain_get_max_threads -> MKL_Read_ThreadENV_Count_Cores (which reads
     /proc/cpuinfo) -> omp_get_num_procs -> __kmp_serial_initialize (OpenMP environment parsing, settings
     dump, system-tick calibration). Each runs exactly once per process.
   - **Why the declared mechanics miss it.** perf's DWARF unwinder stops at MKL_Read_ThreadENV_Count_Cores.
     The statically linked MKL carries no CFI; the CFI build covers hven only. So no sample shows
     ensure_solver_initialized. The frozen map's leaf fallback then files the samples:
     - leaf in libiomp5 -> B_fac;
     - leaf in libc (strcmp, read, vsnprintf, sscanf) -> unmatched -> B_eng.
   - **How much** (marker = a chain containing ensure_solver_initialized, MKL_Read_ThreadENV_Count_Cores,
     __kmp_serial_initialize or __kmp_do_serial_initialize):
     - hs010: 54.5 % of solver instructions (~1.3e6 of 2.39e6 per run), filed B_fac 0.229, B_eng 0.315,
       B_setup 0.001;
     - HS100MOD: 32.8 %, filed B_fac 0.142, B_eng 0.185, B_setup 0.001.
   - **Two alternative readings** (init_audit.py; same thresholds, rho and agreement):
     - **A. Init filed as B_setup** (the brief's own definition: "one-time solver ... construction").
       - hs010: (B_sym+B_fac) = 0.190, B_setup = 0.710 dominant.
       - HS100MOD: 0.279, B_setup = 0.558 dominant.
       - DN-1 does NOT fire for the IPM. "No dense build"; dominant B_setup on both median cells.
       - Population: (B_sym+B_fac) >= 0.40 on 0/22 HS cells and 18/97 small-dense cells.
     - **B. Init excluded** (steady state; the declared secondary reading's stated intent).
       - hs010: 0.417 (B_setup .363, B_eng .133).
       - HS100MOD: 0.415 (B_setup .343, B_eval .132).
       - Same median cells. DN-1 FIRES (marginally; see note 5).
       - Population: >= 0.40 on 16/22 HS and 41/97 small-dense.
   - **Projection.** If a dense arm keeps calling MKL (LAPACK dsytrf through the same threaded MKL), it pays
     the same OpenMP initialization. The init portion of B_fac is therefore not a saving a dense arm could
     project.

6. WHAT THIS LEAVES FOR THE SETTLER
   - The declared reading says DN-1 fires for the IPM, under the agreement clause read as declared.
   - Two facts outside the declared mechanics bear on it:
     - (a) pooled small-dense agreement is 0.976;
     - (b) a third to a half of each median cell's solver instructions is process-once OpenMP initialization,
       which the frozen map files as B_fac + B_eng. Filed as B_setup, DN-1 does not fire and B_setup is the
       IPM's small-problem lever. Excluded, DN-1 fires by 1-1.6 SE.
   - The SQP's DN-1 (DN-0) is unaffected: it never calls ensure_solver_initialized. The milestone outcome is
     DN-1 either way.
   - Whether (b) is a reading question, or a lever (moving or avoiding the OpenMP init, a B_setup item of
     ~1.3e6 instructions per process, which is ~18 % of an HS IPM process and ~55 % of its non-loader work),
     is not this round's to decide.
