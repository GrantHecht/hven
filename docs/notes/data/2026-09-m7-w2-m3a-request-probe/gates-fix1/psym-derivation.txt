M7 W2 M3a FIX ROUND 1 -- THE P-SYM MOVER SHAPE, DERIVED BEFORE THE GATE RAN
===========================================================================

WHY THIS FILE EXISTS. `gates-fix1.sh` ASSERTS a P-SYM mover shape -- differing
objects, class A, class B -- that must be DECLARED before the chain is detached
and never discovered from the chain's own run. Task A could derive its shape by
argument, because its change moved `sizeof(SqpCounters)` 848 -> 856 and the
universe was "every TU that lays the struct out", measured once before at M7 W2
M2 on the same struct (54 = 5 + 49, then 54 = 6 + 48).

FIX ROUND 1'S CHANGE IS NOT THAT KIND. It moves NO offset and NO `sizeof`: the
field `restoration_sub_status` changes TYPE from `SolveStatus` to
`RestorationSubStatus`, same underlying type, same width, same padding. So the
object-level footprint does not follow from the file list, and predicting it
would have been a guess dressed as a derivation. It was MEASURED instead, on
this box, at the two commits the gate compares, BEFORE `gates-fix1.sh` was
written and committed. This file is that measurement.

WHAT WAS RUN. One hold of /tmp/box-build.lock; no solver; `ctest` not involved.
A Debug tree and a Release tree, both already built at the fix round's head,
were hashed object by object; the tree was then checked out at the base commit
and both trees REBUILT AT THE SAME BUILD PATHS (the P-SYM precondition), and
hashed again. The branch was restored before anything else ran.

  WHY EXACTLY THOSE THREE. They are the three TUs that expand
  `HVEN_SQP_COUNTERS_FIELDS` into a gtest `EXPECT_EQ` per field without having
  been edited by this round. An `EXPECT_EQ` on an enum instantiates template
  symbols that carry the TYPE'S NAME -- `PrintToString<T>`, `CmpHelperEQ<T,T>`,
  `UniversalPrint<T>`, `RawBytesPrinter::PrintValue<T,4>` and eight more --
  so renaming the type ADDS symbols to precisely the objects that compare or
  print that field. Counted directly, after the change:

    test_qp_cap_levers.cpp.o                                               12 symbols naming RestorationSubStatus (Debug)
    test_sqp_solver.cpp.o                                                  12 symbols naming RestorationSubStatus (Debug)
    test_start_point_projection.cpp.o                                      12 symbols naming RestorationSubStatus (Debug)

  and the OTHER 169 objects in each tree are byte-identical in Release and
  instruction-identical in Debug. The many among them that DO include one of
  the two changed headers are this round's NEGATIVE CONTROL -- the classifier
  counts them itself -- and it is large rather than scraping the minimum of 1.

===========================================================================
WHAT THE GATE DOES WITH THIS
---------------------------------------------------------------------------
`gates-fix1.sh` declares EXPECT_PSYM_DIFFERING=12, EXPECT_PSYM_CLASS_A=9,
EXPECT_PSYM_CLASS_B=3 and asserts them for EQUALITY in both configs, and
`assert_same_classification` requires the two configs' classifications to be
byte-identical. This derivation predicts both. If the gate reports anything
else, the gate FAILS and the shape is re-derived and declared again -- it is
not adjusted to whatever the run produced.

A NOTE ON WHAT THIS IS NOT. This is not a P-SYM run: `psym_compare.sh` was not
invoked, no capture was taken, and nothing here is offered as the gate's
evidence. It is the DERIVATION of the number the gate will assert, recorded so
that a reader can see the number was fixed, and how, before the chain ran.
