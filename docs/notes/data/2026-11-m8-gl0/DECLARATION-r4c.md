# M8 GL-0 -- DECLARATION-r4c (successor to DECLARATION-r4b.md, committed before the r4c test change and legs; r4 and r4b stay as written)

r4b's chain (code head `6107b2c61`) again stopped at Release ctest on the same test, `SqpGl0.TheSwitchingRatioRaisesNoFloatingPointFlagAtZeroViolation` (FE_INVALID read; evidence `r4/run2-failed/`), although the helper now divides only on a nonzero divisor. A standalone harness compiled with the library's Release flags (`-O3 -ffast-math -fno-finite-math-only -march=native`) reads no flag from any of the four helper calls when each call's flags are read right after it. The test therefore measured something other than the helper: the build is `-ffast-math` (no FENV_ACCESS), so the optimizer may move floating-point operations of the test body (the result comparisons) across the opaque `fetestexcept` call, and the flag word read was not the helper's. The helper is correct; the test's observation was not isolated.

The assertions on the values are unchanged. No product code moves relative to r4b. The helper's divide-on-a-nonzero-divisor form (r4b) stays: it is the form that holds under a speculating optimizer.
