production TU's lines move here: `src/qp/qp_engine.cpp`, whose own `.cpp` gained
`#ifdef HVEN_TESTING` blocks. Its `assert()` sits ABOVE every one of them, so no
`__LINE__` immediate moves and the INSTRUCTION stream cannot.

Nothing else can move, for a reason stronger than measurement: `qp_walk_trace.h`
is entirely inside its own `#ifdef HVEN_TESTING`, so a production compile skips
the whole file -- the line this round added to it, and the new header that line

no line-table record to any production object. `include/hven/detail/qp/qp_engine.h`,

4. THE NON-VACUITY GUARDS
--------------------------
A zero declaration is stronger than a non-zero one, and the way a false zero
could pass is a capture that compared nothing. Three guards stand against that
and the gate asserts all three:

  * both `psym_compare.sh capture` return codes, with non-empty manifests
    (`assert_capture`);
  * equal object counts on the before and after arms (`assert_capture_pair`);
  * a non-zero NEGATIVE CONTROL -- objects that DO include a changed header and
    are byte-identical anyway. Here that control is large and is the
    derivation's own witness: EIGHT library objects name `qp_walk_trace.h` in
    their Ninja dependency lists (`assembly_eval_seam`, `console_trace_sink`,
    `sqp_print`, `sqp_solver`, `soc_elastic_restoration`, `ipqp_engine`,
    `qp_engine`, `continuation`), and SEVEN of them must be byte-identical in
    Debug regardless. `MIN_NEGATIVE_CONTROL = 1`.
