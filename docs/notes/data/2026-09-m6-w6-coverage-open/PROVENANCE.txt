HOW IT WAS RUN (and the two places it departs from `scripts/run_coverage.sh`)
  The script owns the path; this read ran the script's own steps as separate
  legs, because the box protocol caps a single foreground call and the whole
  suite does not fit in one:
    1. configure  `cmake --preset linux-clang-coverage`
    2. build      `cmake --build build-coverage -j 8` in three target slices
                  (hven; the four test targets; the rest)
    3. suite      four `ctest` slices, `-I` index ranges, `-j 4`, each with
                  LLVM_PROFILE_FILE="$PWD/build-coverage/profiles/hven-%p.profraw"
                  -- the script's own spelling (:108) -- so every test process
                  writes its own raw profile into one directory
    4. the one long cell ALONE (below)
    5. report     `scripts/run_coverage.sh --report-only`, the script's own
                  documented mode: llvm-profdata merge + the three llvm-cov
                  invocations over ctest's own binary registry
  DEPARTURE 1: the suite ran in slices rather than as one ctest invocation. The
  union of the four slices is the whole registry -- reconciled BY NAME, not by
  index (`-E`/`-I` renumber ctest's output): 2544 registered names, 2544 seen.
  DEPARTURE 2: `ctest -j 4`, not serial. Nothing here asserts wall-clock, so
  CLAUDE.md section 7's serial rule is not engaged; and no cell failed, so no
  "deviation observed under a co-run" arose to re-run alone. MKL_NUM_THREADS=1
  and OMP_NUM_THREADS=1 in every slice.
