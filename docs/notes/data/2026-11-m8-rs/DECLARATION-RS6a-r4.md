# RS-6a -- DECLARATION r4 (instrument defects found by gate run 1; DECLARATION-RS6a.md, -r2 and -r3 stay frozen)
Gate run 1 (gates/RS-6a/VERDICTS.txt, head 185586a41, base 2f43fee5e) ran every leg once. The code legs passed (G1 build, G3 flags, G4 PCH, G5 lists/ctest in Release and Debug, G6 install smoke, G7 replay, G9 sweep, membership guard);
five INSTRUMENT defects (none a tree defect) made five legs fail or not run, and they are corrected here. The tree under test is unchanged by this successor: tests/, src/, include/, bench/, scripts/ and every CMakeLists.txt are byte-identical between 185586a41 and the head the second chain runs on (only docs/notes/data/2026-11-m8-rs/{tools,legs} and this file change);
the arms captured by run 1 (.scratch/g6/arms) and the build under test are re-read, not rebuilt, so no result was selected by rerunning a build.
1. rs6a_objmap_check.py keyed an object by its source path alone; bench/ipm_corpus_leg.cpp is compiled into TWO targets (hven_sqp_corpus and the test executable), so the tool aborted ("built twice"), the object map was never written, and psym-compare/psym-union found no map.
   Fixed: objects are paired by identical (target, source) first, then the leftovers by source alone, which must be unambiguous. The criterion is unchanged: generated map == declared maps (r1 + r2). Run on run 1's two manifests: 89 lines generated, 89 declared, equal.
2. gate6a.sh read the membership table from build/tests/; the configure writes it to build/ (the top-level binary directory). Fixed; standalone step `membership`.
3. G2's unity class (psym_union.py), made precise after the first look at real data. The instrument measured the class and found the declared "identical per symbol" cannot hold for a RE-COMPOSED batch even though every source line is unchanged: the same test bodies compiled in a different unity neighbourhood get different
   inlining and register-allocation decisions (stack-frame displacements, branch offsets, register choice) in a small fraction of symbols. What is asserted for the class is therefore, in order: (a) the SET of test-defined functions (anonymous-namespace members and everything named for a test) is equal before and after;
   (b) the multiset of registration calls made by the `_GLOBAL__sub_I_*` entry points is equal (assembler-local labels and exception-unwinding helpers excluded: their number follows inlining); (c) function bodies are compared in tiers -- identical, identical modulo numeric operands, differing beyond numbers --
   with every symbol of the last tier listed in gates/RS-6a/psym-union-detail.txt and the counts in RESULT; template/inline-function symbols (std::, Eigen::, testing::, fmt::, library inlines) present in only one side are listed as informational (composition-dependent inlining).
   Behaviour is not asserted through instructions here: G5 (the union of the gtest lists equals the base and every test passes in Release and Debug, 3890/3890) is the behavioural evidence for the class, and G2 for every NON-unity object stays byte/symbol identity through the object map.
   Normalisations added to the tool, each a layout or numbering artefact of an object file: digits of assembler-local labels (`.LCPI*`, `.L.str.N`, `.Lconstinit.N`) -- the CONTENT of constant pools is data and is not compared (the declared limit of this instrument); the label objdump prints for a RELOCATED branch (nearest symbol of the placeholder address);
   a rip-relative displacement that the assembler resolved (spelled by the target symbol instead of a layout distance). Self-tested: a class compared with itself is identical; two different classes differ.
4. mutation6a.sh refuses a dirty tracked tree, and the instrument edits above were uncommitted when run 1 reached it (rc=2): a process error. Committed before run 2.
5. q9.sh found q9_measure.py only inside the worktree being measured; the base worktree does not hold it (the base arm aborted: rc=2 twice). Fixed: the tool is read from next to the script. The after arm of run 1 measured correctly (gates/RS-6a/q9/after-*.json) and stands; run 2 measures the base arm (step `q9base`).
