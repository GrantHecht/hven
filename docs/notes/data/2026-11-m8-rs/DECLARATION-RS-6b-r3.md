# RS-6b -- DECLARATION r3 (leg L4's comparison criterion refined; DECLARATION-RS-6b.md and -r2 stay frozen)
Written after the first L4 comparison (gates/RS-6b/objcmp.txt, base 48e1eeae2 vs head 72cc139df, same build path, __FILE__ neutralised): 64 of 67 non-test objects byte-identical, libhven.a member set identical, ctest -N identical (3927 names each) and every executable's gtest list identical; the three that differ are bench objects (bench_corpus.cpp.o, bench_crossover.cpp.o, ipqp_e1_arm.cpp.o) whose strings differ in exactly one literal, the configure-time commit stamp (`snopt-shim-base-1-44-g48e1eeae2ced` vs `snopt-shim-base-1-52-g72cc139dfba6`, HVEN_SQP_CORPUS_GIT_DESCRIBE; 14 bytes differ in each). The original criterion ("every non-test object byte-identical, 0 movers") did not foresee that a stamp derived from `git describe` differs between any two commits; under it the leg failed, so it is re-derived here, not waived.
## The criterion of this r3 (applied to the same snapshots, no rebuild)
Every non-test object is byte-identical, EXCEPT the objects that embed HVEN_SQP_CORPUS_GIT_DESCRIBE, which must be byte-identical after the two stamp strings are replaced by one placeholder of the same length in each snapshot copy (comparison on copies; the snapshots are untouched). The set of stamp-embedding objects is DERIVED, not listed by hand: every object whose `strings -a` contains the base's or the head's stamp string. A non-test object that differs and is not in that set, or that still differs after normalisation, fails the leg. libhven.a members unchanged. No library object (anything under CMakeFiles/hven.dir) embeds the stamp (the leg reports that count). The three differing objects are exactly the set the derivation must find (a fourth would be reported).
Tool: gates/RS-6b/objcmp_r3.py (written for this leg, committed with the evidence).
