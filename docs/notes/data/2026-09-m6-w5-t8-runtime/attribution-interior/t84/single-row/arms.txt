M6 W5 T8.9r-attrib5 -- THE THREE ARMS OF THE SINGLE-ROW INTERIOR LEG, AND THEIR
VERIFICATION
============================================================================

THE LEVER IS A COMMIT ON m6, NOT A SCRATCH PATCH. `--internal-run-one <cell>
--engine interior --treatment T --internal-out <path>` runs exactly one base row
of the interior leg in process and writes it under the leg's own header. It is
d5931e8 (`bench(corpus): M6 W5 T8.9r -- a single-row interior process ...`), bench
and test source only; both configs' `libhven.a` are byte-identical across it
(Release 60bfe03f79078eb8ab51fd099a7253f91e232714a008a52be0a40e49403fa30a, Debug
3efe888df9b940bcdc02e85bb365e401c2e89130c96c17e06e565dd3a5de6035).

THE ARMS ARE NOT AT THAT COMMIT. They are `git archive` extractions of 510a4bb
and 9cebbbe with the lever's edits applied by `scripts/adapt_arm.py`, because the
committed diff cannot be `git apply`-ed to trees that old: at both of those
commits `write_interior_provenance` has no `parts2` parameter (that is T8.9's)
and the surrounding text has moved. The script performs the SAME EDITS against
anchors those trees do carry, and `adapted-lever.patch` is the resulting diff,
retained verbatim.

  THE TWO ARMS' ADAPTED PATCHES ARE BYTE-IDENTICAL TO EACH OTHER. 510a4bb's and
  9cebbbe's `bench/bench_corpus.cpp` and `bench/ipm_corpus_leg.h` are themselves
  byte-identical (9cebbbe changes the leg's `.cpp` only, in the field names it
  reads off the result), so the lever is common-mode by construction and the
  build log of each arm asserts the equality before it configures.

  THE tests/ HALF OF THE LEVER IS NOT APPLIED. These builds are
  -DHVEN_BUILD_TESTS=OFF and compile no test target.

THE RECIPE, the T8.9r artifact's own, verbatim:

  cmake -S <arm> -B <build> -G Ninja -DCMAKE_BUILD_TYPE=Release
        -DCMAKE_CXX_COMPILER=/usr/bin/clang++ -DCMAKE_C_COMPILER=/usr/bin/clang
        -DHVEN_BUILD_TESTS=OFF -DHVEN_BUILD_BENCH=ON -DHVEN_A4_GATE=OFF
  cmake --build <build> --target hven_sqp_corpus -j 8
  CCACHE_DISABLE=1 on both, in the environment of both.

BOTH ARMS' `libhven.a` REPRODUCE THE EARLIER LEGS' BYTE FOR BYTE -- 510a4bb's is
`../../attribution/arms.txt`'s a04 and `../arms.txt`'s b01, 9cebbbe's is
`../arms.txt`'s b03. That is the check the brief made a STOP condition: the lever
touches no library code, and the library each arm links is the library the wall
legs measured. The build logs assert it inline
(`logs/A01-build-510a4bb.log`, `logs/A02-build-9cebbbe.log`), and the control's
executable is `cmp`-equal to the parent's.

The arm directory names are the same length (bin/510a4bb, bin/9cebbbe,
bin/control), which is what keeps the measured child's argv byte length identical
across arms for the same row -- the layout lock `../../attribution/raw/arm_leg.sh`
introduced. Every run prints its own ARGV_LEN into the batch log.
