THE CHANGE UNDER TEST (the settler's rulings R1-R11; every premise was checked in code first)
--------------------------------------------------------------------------------
R1  AcceptanceStrategy::retract_last_acceptance() (default no-op), called on the IPM rollback path.
    Funnel: the width saved before register_accepted_step. Filter: the filter and its three
    reset-heuristic fields (an H-type accept augments it and any accept runs the reset heuristic, so
    the filter DOES register state for the step). Modern merit: pi_l and the smallest-known tracker
    (both move only on an accept; nu and pi_u move on every trial and are kept). Armed by an accept,
    disarmed by the next acceptance test, reset() and a phase switch.
R2  step_cap resets only when a step that moved the point (alpha > 0) is followed by a clean screen of
    the point it reached. TERMINATION, restated: a rollback sets cap <- cap_k * alpha_k /
    backtrack_divisor (cap_k, alpha_k the rolled-back step's), so each rollback divides the cap by at
    least backtrack_divisor; alpha = 0 iterations leave it alone; it returns to 1 only after a clean
    screen of a moved-to point. Hence a run of rollbacks with no such screen between them crosses the
    floor backtrack_divisor^-line_search_max_backtracks within line_search_max_backtracks rollbacks, and
    the failure that would take it below the floor ends the phase kNonFiniteIterate (at the failed point,
    R7) instead of rolling back. Every iteration still counts against max_iterations.
R3  init_impl screens the kInit evaluation (objective, gradient, KKT values, right-hand side) BEFORE
    compute()/refactorize(); a failure skips the factorization and the multiplier solve, hands a claimed
    analysis back, and the phase's first iterate ends kNumericalError (kNonFiniteStart at the start
    point; kNonFiniteIterate at a re-initialization between phases, where an EvaluationError is the same
    failure instead of propagating). The initial factorization's outcome (KktFactorization::info()) is
    read before the solve: a failure is kNumericalError, stop reason kNone, a message naming the initial
    KKT factorization, last_kkt_info recorded -- never SymmetricFactor's precondition error. Both
    init_impl call sites (solve entry and the between-phase re-init) share the one code path.
R4  rollback_valid = false at the restoration entry continue and the four restoration-exit continues.
R5  SQP: SolveState::at_start (cleared at the first commit and at a restoration return) replaces the
    value comparison with x0.
R6  SQP: st.derivative_failure written where a bundle becomes st.ev (commit, promoted SOC point, box
    projection, restoration resume, best-iterate restore); the QN-on-reject refresh and the restoration
    candidate upgrade use their own strings.
R7  CHOICE: both engines return the point P whose evaluation failed, multipliers (row and bound) cleared,
    on every kNonFiniteStart / kNonFiniteIterate exit. JUSTIFICATION: the last finite point exists only
    on the floor exit -- at the start point, a phase's first iterate and inside restoration there is no
    snapshot -- so "the last finite point" cannot be one rule; P with cleared multipliers is the rule
    every exit can keep, it is what the SQP's non-finite evaluation exit already returned, and the
    message names the quantity and where. Changed to fit: the IPM floor exit (no longer restores then
    exits), the IPM no-rollback exits (multipliers were the committed step's), and the SQP non-finite
    SUBPROBLEM exit (it kept the multipliers). The residual fields report what P's evaluation measured,
    NaN where it measured nothing. Docs: the ipm_solver.cpp block comment, core/solver_status.h (both
    enums), core/errors.h.
R8  last_result() holds only the partial of a solve an exception escaped (argument refusals included);
    cleared at solve entry, not written on a returned solve. Docs on both handles and impls.
R9  finish_interrupted_result (both handles) sets status kInterrupted and the fixed message before any
    fallible call.
R10 std::logic_error: SymmetricFactor factorize-before-analyze, require_solvable (solve/solve_partial/
    share before a successful factorize; stale adopted numerics) on both adapters;
    DenseSymmetricFactor::solve before factorize and its pivot-data guard; SchurComplement::
    expected_neg_eigs_delta; SsnEngine's three structure-map invariants; IpqpKktLayout's three; the SQP
    IPQP kNone invariant. BackendError (still a std::runtime_error, so every catch that degrades on it
    keeps degrading): SchurComplement::solve on an exactly singular C (the QP engine's border path
    catches it as its singular-C signal), Factorization::solve on a session a co-owner's failed
    factorize left without numerics (the holder saw no outcome to check). Audited catch sites that read
    std::runtime_error (equality_basis.cpp x7, qp_engine.cpp x8, kkt_factorization.cpp x1): each guards a
    BackendError or a status-gated call; none relied on a precondition throw. Session files untouched.
    errors.h: hven throws no other std::runtime_error.
R11 the tests below. Also found and fixed while writing the R11 thread-pool pin: a foreign exception
    thrown by the DISPATCHING thread's own partition was rethrown only when no pool lane threw, so a pool
    EvaluationError hid it; DispatchContext::rethrow_if_exception now takes it and applies the
    documented preference across all lanes. And: the kNone kNumericalError message carries its detail
    (empty on every exit but R3's), and a successful rollback no longer writes stop_detail_.
FIXTURE REACHABILITY: SqpStopReason::kRestorationNonFinite IS reachable without a seam (pinned:
    RiderRestorationStop -- the objective NaN near the violation's stationary point). kRestorationNoClaim
