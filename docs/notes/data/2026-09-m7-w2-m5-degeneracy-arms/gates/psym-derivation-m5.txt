4. THE P-SYM MOVER SHAPE -- DECLARED: ZERO, IN BOTH CONFIGURATIONS
------------------------------------------------------------------
    Release   DIFFERING 0 = class A 0 + class B 0
    Debug     DIFFERING 0 = class A 0 + class B 0

and therefore `psym_compare.sh compare` must exit 0, not 1.

A ZERO DECLARATION IS STRONGER, NOT WEAKER, and the thing that could make a
false zero pass is a capture that compared nothing. Three guards, all asserted
inside G5: both capture return codes enter the gate with non-empty manifests;
the two arms' object counts must be equal; and the negative control must be
non-zero -- at least one object that DOES include a changed header and is
byte-identical anyway.

5. THE DEBUG-ONLY SHAPE -- DECLARED: Release 0, Debug 1
--------------------------------------------------------
Release declares that NOTHING may differ at all, in any section, in any of the
42 library objects.

Debug declares EXACTLY ONE object differing in DEBUG SECTIONS ONLY, and it is
`src/qp/qp_engine.cpp.o`. Why exactly one: no production translation unit gains
a LINE (section 2), so only the TU whose own `.cpp` source lines moved can have
a different DWARF line programme, and its instruction stream cannot move
because its one `assert()` sits above every hunk.

This is the shape M4 and M4 fix round 1 BOTH measured (42/42 byte-identical in
Release; 41 byte-identical and qp_engine.cpp.o debug-only in Debug). G5b is
what TESTS it: a SECOND Debug object, ANY Release object, or a difference in a
NON-debug section each FAIL the gate.
