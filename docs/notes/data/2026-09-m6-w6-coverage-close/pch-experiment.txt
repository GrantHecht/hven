AN EXPERIMENT, NOT PART OF THE READ. Every number in this file comes from two
SMALL instrumented trees built for this question alone. They are comparable to

to T0's. Nothing here is a pin, a baseline or a timing. Apple/Accelerate:
UNOBSERVED.

THE QUESTION T0 NAMED
---------------------
T0 found four library headers reporting 0.00 % lines while their functions
demonstrably execute, and observed that TWO of them (timer.h,
inertia_regularization.h) are named in src/hven_pch.h while TWO
(eval_error_log.h, ipm_solver_types.h) are not. It called that a CORRELATION,
not a cause, and named the cheap test: one coverage tree with the precompiled
header off, re-read the same way.

THE ARMS, AND THE ONE VARIABLE
------------------------------
Two trees under .scratch/w6t2/ (git-ignored), configured with the
linux-clang-coverage preset's OWN cache variables spelled out -- Debug,
clang 22.1.8 for C and C++, HVEN_FP_MODE=SAFER_FAST,
"-fprofile-instr-generate -fcoverage-mapping" on both languages and
"-fprofile-instr-generate" on the exe linker. The preset itself pins its
binaryDir to build-coverage/, which the close read owns, so the variables are
passed directly instead; that is the ONLY departure from the preset and it
changes no flag.

The arms differ in exactly one cache entry:
    ARM 1  (PCH ON)   the shipped configuration
    ARM 2  (PCH OFF)  -DCMAKE_DISABLE_PRECOMPILE_HEADERS=ON
CMake's own switch, honoured since 3.16. NO source, CMake or preset change was
made for this experiment, and none is needed: src/CMakeLists.txt's deferred
opt-out loop only sets and reads SKIP_PRECOMPILE_HEADERS source properties,
which configure identically either way.

PROOF OF REACH, both directions, from each arm's own compile_commands.json:
    ARM 1   "-include-pch" occurrences: 4   (the four opt-in sources)
    ARM 2   "-include-pch" occurrences: 0

A REDUCED OBJECT SET, DECLARED. Each arm builds and runs `hven_interior_tests`
and `hven_drivers_tests` only -- the two binaries whose cells reach every row
under examination -- rather than the whole suite. Both arms run the same two
binaries over the same cells, which is what makes them an A/B.

WHAT IT SETTLES, AND WHAT IT DOES NOT
-------------------------------------
1. THE PRECOMPILED HEADER IS A LARGE PART OF THE CAUSE. All four of T0's
   under-read rows fill in when it is off, and the mismatched-function count
   over this object set falls from 126 to 92. The count does NOT fall to zero,
   so the PCH is not the whole of it -- M5's diagnosis (the bounded,
   understating HVEN_TESTING double-compile effect,
   docs/notes/2026-08-m5-ledger.md:616-617) still accounts for a remainder, and
   this experiment neither confirms nor refutes that part.

2. IT CORRECTS T0's FRAMING OF ITS OWN CORRELATION. T0 (README section 5, item
   3) restated the correlation as "two under-read headers are IN the PCH and
   two are NOT, so the experiment can test the PCH contribution only and cannot
   settle all four rows". It settles all four. The effect does not follow
   "listed in src/hven_pch.h"; it follows "this header's inline body is
   compiled inside a TU that CONSUMES the PCH" -- and all four are, because
   src/drivers/ipm_solver.cpp is one of the four opt-in sources and includes
   eval_error_log.h and ipm_solver_types.h. T0's caution was right about the
   inference being unproven and wrong about which way it would go.

3. IT IS NOT A REASON TO CHANGE THE BUILD. The PCH's membership list is
   evidence-gated on compile time AND byte-identical objects
   (src/CMakeLists.txt's own rules, scripts/check_pch_neutrality.sh), and this
   is a REPORTING defect in an instrument tree, not a defect in the shipped
   library. What it buys is knowing which rows to stop chasing: a future
   coverage read that wants those rows read correctly can take the reduced
   PCH-off arm alongside the main read, at the cost of one extra build.

4. IT SAYS NOTHING ABOUT THE CLOSE READ'S NUMBERS. Those were taken with the
   shipped configuration, PCH on, exactly as T0's were -- which is what makes
   the delta in delta.txt attributable to the tests and to nothing else.

5. soc.h IS AT 100 % IN BOTH ARMS. The one header T0 judged genuinely cold is
   covered with the PCH on and with it off, which is the control this table
   needed: the experiment moves rows that were misreported, and does not move a
   row that was honestly read.
