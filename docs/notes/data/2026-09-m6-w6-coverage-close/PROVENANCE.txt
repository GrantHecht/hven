THE "MISMATCHED DATA" WARNING, RE-COUNTED, AND ITS CAUSE MEASURED
  llvm-cov warned "952 functions have mismatched data" on this read.
    M5's first CI coverage run .... 736   (ledger :457-458)
    W2 T8's read .................. 683
    W6 T0's read .................. 952
    THIS read ..................... 952   -- unchanged
  The count did not move, which is itself informative: T2 added 45 test cells
  and no library source, and this effect does not track how much is tested.
  What DID move is the understanding of its cause. `pch-experiment.txt` in this
  directory measures a controlled A/B -- the library's precompiled header on and
  off, same reduced object set, one variable -- and finds that ALL FOUR of T0's
  demonstrated under-read headers fill in with the PCH off, while the
  mismatched-function count over that object set falls from 126 to 92. So the
  precompiled header is a large part of the cause and not all of it; M5's
  HVEN_TESTING double-compile diagnosis (ledger :616-617) still accounts for a
  remainder, which this experiment neither confirms nor refutes.
