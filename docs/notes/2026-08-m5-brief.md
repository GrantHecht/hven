M5 makes the two engines peers: each usable standalone from a consumer,
selected per solve call, warm-startable from a value, with the IPM → SQP
crossover expressed as one composition of two standalone-capable engines

## 2. Normative requirements (R1–R6, from the spec)

- **R1** — the warm-start currency is value-semantic and serializable:
  neutral core (primal, equality/inequality/bound multipliers) + opaque
  engine extensions + structure-identity stamp.
- **R2** — the IPM exports its polish handoff (multipliers + mu-hat) into
  extensions.
- **R3** — both engines accept a core-only payload; foreign extensions are
  ignored without error.
- **R4** — engines report per-solve outcome values (flag, iterations,
  objective, KKT residuals, timing) sufficient to fill the consumer's
  StageResult.
- **R5** — applying a warm payload is non-consuming and deterministic: same
  payload, same start state.
- **R6** — hot-state reuse is never observable in answers; a reuse form that
  cannot guarantee that is not silently enabled.

## 3. The currency — concrete surface

New component `include/hven/warmstart/` (public), `src/warmstart/` (TUs),
namespace `hven::solvers`. Names below are the surface tycho's plan may cite.

```cpp
/// One opaque engine extension: a tag naming the producer and meaning, and
/// bytes only that producer interprets. Serialization is the pair verbatim.
struct WarmExtension {
    std::string tag_;                 // e.g. "hven.ipm.polish.v1"
    std::vector<std::byte> payload_;

    friend bool operator==(const WarmExtension &, const WarmExtension &) = default;
};

/// The warm-start currency (R1). Value-semantic, comparable, serializable.
///
/// SPACE CONVENTION: every block is stated over the DECLARED problem — the
/// full primal space and the declared row spaces — never over a solver's
/// reduced space. The stamp carries the treatment conjunct (M4, E2 ruling),
/// so a payload taken under one treatment refuses against a problem laid
/// under another; inside one stamp the declared space is the one space both
/// engines share.
struct WarmStartData {
    Eigen::VectorXd primal_;            // n
    Eigen::VectorXd eq_lmults_;         // me
    Eigen::VectorXd iq_lmults_;         // mi
    Eigen::VectorXd bound_lmults_;      // n, signed z = -zL + zU (Task 8 convention)
    ModelStructureKey structure_key_;   // the stamp; == is the currency test
    std::vector<WarmExtension> extensions_;

    friend bool operator==(const WarmStartData &, const WarmStartData &) = default;
};
```

Serialization: `serialize(const WarmStartData &) -> std::vector<std::byte>`
and `deserialize(span<const std::byte>) -> WarmStartData` in the same header,
versioned with a leading format tag; extensions round-trip as tagged bytes
(the spec's pickle/cross-process commitment sits on this pair). Malformed
input refuses by `std::invalid_argument` naming the offset and expectation.

Engine surface (both engines):

```cpp
WarmStartData export_warm_start() const;             // from the last completed solve
void         stage_warm_start(const WarmStartData &); // R5: non-consuming, const-ref
```

- `stage_warm_start` REFUSES on stamp mismatch (`structure_key_ !=` the
  bound problem's `model_structure_key()`), `std::invalid_argument` naming
  BOTH keys via `digest()` — the spec's stale-warm refusal is a re-surface
  of this refusal.
- Foreign or unknown extension tags are skipped silently by design (R3):
  capability downgrade, distinct from structural staleness.
- Determinism (R5) is pinned: staging the same payload twice from cold
  produces bit-identical first iterates.

R2: the IPM's export carries `"hven.ipm.polish.v1"` — the polish handoff
(bound multipliers in the reduced arrangement it hands its own crossover
today, plus mu-hat), bytes documented in the extension's own header block.
The SQP engine consumes that tag when present; absent it, core-only start
(R3 pin: same problem, core-only payload, both engines accept and converge).

R4: outcome values already exist on `SolveResult` (`iter_num_`, objective on
the caller's scale, KKT residual set, `bound_lmults_`,
`fixed_variable_treatment_`); M5 adds nothing to them beyond a wall-time
field and the audit that both engines fill the same set — the audit's gaps,
if any, are the work.

R6: the only hot state the engines carry across solves today is the
epoch-gated symbolic analysis (M4). The rule of record: reuse keyed on the
structure epoch is answer-neutral BY CONSTRUCTION (same pattern, same
symbolic); any future reuse form that cannot make that argument ships
default-off. A pin asserts cold-vs-hot bit-identity on an unchanged-epoch
re-solve for both engines.

## 4. Work packages

- **W1 — currency extraction.** `WarmStartData` + serialization + the two
  engine entries, IPM first (its staging seeds exist:
  `staged_eq_mults_`/`staged_iq_mults_` and the bound-dual snapshot);
  declared-space mapping at the boundary (reduced → declared on export,
  declared → reduced on staging, under the stamp's treatment conjunct).
- **W2 — R2/R3 export-consume.** The polish extension, both directions,
  with the crossover replay pinning equivalence to today's privileged
  handoff (bit-identical where the handoff is bit-identical today).
- **W3 — SQP standalone entries.** The SQP engine reachable without an
  IPM in the call chain: cold and warm-started, driven directly by a
  consumer (mesh refinement / continuation drive it with values). Solver
  selection itself is consumer-side (the spec's one-verb surface); hven's
  obligation is that both engines expose the same bind/solve/report shape.
- **W4 — R4 audit + wall-time field.**
- **W5 — crossover measurement.** Replay-corpus crossover legs (IPM-only,
  SQP-only, IPM→SQP value-warm, IPM→SQP with polish extension), counters
  asserted, wall informational, under §5's instrument constraints.
- **W6 — R5/R6 pins** as stated in §3.

Sequencing: W1 → W2/W3 in parallel → W4–W6. The tycho plan can start at
W1's surface (this brief); nothing tycho-side gates on W5.

## 5. Measurement discipline for M5

- The **instrument-resolution constraint** (M4 Task 9 legs, on the record):
  the alternated 3×7 instrument resolves no better than a −1.4…+0.6% null
  floor; any sub-1.4% wall claim needs more ROUNDS (between-process
  scatter), not inner reps. Crossover wall comparisons in W5 are designed
  against this, or stated as informational.
- The **multi-partition nondeterminism** carry (reduction order, contested
  coordinates measured up to 245 columns at 21 partitions) is adjudicated
  in M5, not papered over: W5's bit-identity claims are single-partition,
  or near-ulp-gated with the tycho suite's calibrated gates.
- The **census-cell byte-equality carry**: the ScoreModelSurface pin's
  premise (process-invariant residual last digits) fails on at least one
  box (MKL address-sensitivity); the fix (CNR or near-ulp on those
  columns) lands in the first M5 window and the §7 clause gains its
  caveat.
