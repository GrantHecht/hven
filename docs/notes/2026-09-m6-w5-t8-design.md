## 1. The problem, in one paragraph

The two engines were migrated from two projects and joined by warm-start currency. Today nothing on
their public surfaces is spelled the same: five phase-named IPM entries returning a bare vector against
one `solve` returning a value; fifty validated setters on a mutable settings object against ctor-frozen
options with no accessor; two status enums with the same integer shape and different names and
namespaces; two result structs, two counter models, two iterate-row types, a residual vocabulary that
collides under shared names; one warm-start payload with two protocols; a per-iteration callback on
one side only; and, underneath, two model contracts. The last is deferred (§6); everything else is T8.

## 2. Group 1 — the shared surface

One commit per concern, in this order. Each holds the tree green, migrates tests and bench, and lands
under the OLD class and file names (`InteriorPointSolver`, `SqpDriver`): group 1 changes SHAPE, group 2
renames, so group 1's per-symbol maps stay small and group 2 stays mechanical.

### 2.1 Classes, lifetime, options
- Both classes in `hven::solvers`. **Neither is movable or copyable in T8.** astra and the lane both
  found the promise unfounded: the IPM and `KktFactorization` suppress movement deliberately; the SQP
  holds `QpEngine` by value with backend sessions inside and declares no move. Movability is a
  separate design (ownership of workspace tables, strategy references and backend sessions) and is
  registered, not delivered. tycho's `clone_prototype` keeps returning `unique_ptr` for both.
- `IpmOptions` and `SqpOptions`: aggregate structs, bare `snake_case` fields (the IPM's trailing
  underscores go). Each embeds one `CommonOptions common` for: `threads` (§2.6), `print_level`
  (§2.6), `start_level`. Engine-specific stays engine-specific: the SQP's nested `QpOptions` /
  `IpqpOptions`; the IPM's barrier, acceptance, inertia, restoration, watchdog, return-best,
  fixed-variable-treatment and sparse-backend knobs. CNR (`cnr_mode`) stays IPM-only in T8 (§2.6).
- Validation: one free `validate(const IpmOptions &)` / `validate(const SqpOptions &)` throwing
  `std::invalid_argument`, run at construction and at replacement; today's `Settings::validate()` and
  `validate_sqp_options` become these.
- Construction: `explicit IpmSolver(IpmOptions = {})`, `explicit SqpSolver(SqpOptions = {})`. `const
  XOptions &options() const` on both. `void set_options(XOptions)` on both, legal between solves only
  (`std::logic_error` during a solve; the check is a flag set for the whole public `solve`). On the SQP a
  replacement REBUILDS `engine_` (constructed from `opts.qp`) and drops the lazily built IPQP engine, so
  every outstanding hot handle loses its engine affinity — the next solve degrades to kWarm on its own
  (the structure hash still matches; no refusal) and a pin shows it. On the IPM a replacement invalidates
  the backend session and forces re-analysis on the next solve; trace and ledger attachments survive
  replacement on both. Exception safety: validation runs before anything is torn down; a throwing
  replacement leaves the previous options in force.
- The IPM's ~50 validated `set_*` methods, its four static `strto_*` parsers and its six string-taking
  setter overloads GO. Presets become free functions returning a full value: `IpmOptions
  ipm_preset(std::string_view)` (the existing table) and `SqpOptions sqp_preset(std::string_view)`
  ("default" only until M8's labeled configs).

### 2.2 The solve family
- IPM: `IpmResult solve(NonLinearProgram &model, const Vec &x0, SolveBudget = {})` and `solve(model,
  x0, const WarmStartData &warm, SolveBudget = {})`. SQP: `SqpResult solve(ClaimStreamSource &model,
  const Vec &x0, SolveBudget = {})`, `solve(model, x0, const WarmStartData &warm, SolveBudget = {})`,
  PLUS the labelled SQP-only entry `solve(model, x0, const SqpWarmStart &warm, SolveBudget = {})`
  (§2.4). The model is borrowed for the call on both; the IPM's `set_nlp` / `release`, the `shared_ptr`
  binding and the model-taking constructor go. Cross-solve reuse on the IPM (symbolic analysis, pattern
  hash, partition setup) is keyed on the bound program's identity AND its structure epoch AND the
  fixed-variable treatment in force: a different program object, a bumped epoch or a changed treatment
  re-analyses; the same triple does not. (astra: epoch + declaration key alone is insufficient.)
- The SQP's model-taking overloads that build a bridge per call stay as they are (`const NlpModel &`
  wrappers over `NlpModelAggregate`); they are convenience, not a second contract.
- **The IPM's five phase-named entries become `IpmOptions::phases`**, a sequence of `IpmPhase`
  (`kOptimize`, `kSolve`), default `{kOptimize}`, with the existing rules preserved and now written
  down: the trailing `kSolve` in `optimize_solve` / `solve_optimize_solve` runs ONLY if the optimize
  phase did not converge; the first optimality phase installs the seeded multipliers; each phase
  re-initialises per today's inter-phase rules; a fatal status (`kNumericalError`, `kDiverging`,
  `kInterrupted`) short-circuits the sequence; the empty sequence is `invalid_argument`; arbitrary
  sequences are legal and each of the five legacy names is a documented sequence. The `result()`
  accessor goes.
- **`SolveBudget`** — `{Index minor_budget = 0 /*unlimited*/; Index max_iterations = 0 /*engine
  option*/; }`. On the SQP `minor_budget` is today's probe budget with its accounting unchanged (it
  charges SSN/IPQP work, not only walk minors); `max_iterations`, when non-zero, is `min(budget,
  opts.max_iter)` for the top-level solve only — restoration keeps `opts.max_iter - spent` as today.
  On the IPM `max_iterations`, when non-zero, caps EACH phase at `min(budget, opts.max_iters)`;
  `minor_budget` is ignored and documented so. Exhaustion of a budget cap reports `kMaxIter` (an
  iteration cap) or `kBudgetExhausted` (the probe budget, SQP only) exactly as today; a partial phase
  sequence returns the last phase's result.

### 2.3 Status and result
- `SolveStatus` in `hven::solvers`: `kOptimal`, `kAcceptable`, `kMaxIter`, `kInfeasible`,
  `kStalled`, `kDiverging`, `kNumericalError`, `kBudgetExhausted`, `kInterrupted`. Nine values, not
  eight: astra showed the IPM's `NOTCONVERGED` covers both iteration exhaustion and stalled-stage /
  locally-infeasible-restoration exits before the cap, so mapping it to `kMaxIter` alone would lie.
  Mapping — IPM: CONVERGED→kOptimal, ACCEPTABLE→kAcceptable, NOTCONVERGED→kMaxIter when the cap was
  hit, →kStalled otherwise (the two exit sites are named in the brief), DIVERGING→kDiverging,
  SINGULAR_KKT→kNumericalError. SQP: identity on its five (kOptimal, kMaxIter, kInfeasible,
  kNumericalError, kBudgetExhausted). Reachability, documented per engine: the IPM cannot report
  kInfeasible or kBudgetExhausted; the SQP cannot report kAcceptable, kStalled or kDiverging;
  NEITHER reports kInterrupted today — it is new (§2.5). The qualification that SQP `kInfeasible` is
  not necessarily certified stays on the enum and on `SqpResult::infeasibility_certified`.
- `const char *to_string(SolveStatus)`. `int severity(SolveStatus)` defined for ALL nine (the IPM's
  five-position `operator<=>` extended; order: kOptimal < kAcceptable < kInterrupted < kMaxIter <
  kBudgetExhausted < kStalled < kInfeasible < kDiverging < kNumericalError). Severity is a reporting
  order only: phase termination is governed by the short-circuit rule in §2.2, so `kInterrupted` stops
  the sequence although it ranks below kDiverging. `hven::ConvergenceFlags` and
  `hven::solvers::SqpStatus` go.
- `SolveResult`, a NON-POLYMORPHIC base struct (aggregate inheritance; `r.status`, not
  `r.core.status`; no virtuals, never deleted through a base pointer, slicing documented as
  value-preserving for the base fields). Fields, ALL in declared space and CALLER units: `status`,
  `x`, `lambda_e`, `lambda_i`, `z`, `f`, `stationarity`, `feasibility_e`, `feasibility_i`,
  `complementarity`, `ce`, `ci`, `iterations`, `wall_seconds`, plus `export_warm_start() const`.
- **Residuals are DIAGNOSTICS over the declared NLP in caller units, defined once for both engines,
  and NOT the engines' convergence measurements.** astra's audit: under the same names the IPM measures
  reduced-space stationarity with explicit bound duals and objective scaling retained, a slack-augmented
  inequality residual, and a complementarity over slack, bound and elastic pairs, sometimes of the
  restoration subproblem; the SQP measures projected stationarity on the caller's scale, positive
  inequality violation including bound violation, and inequality-product complementarity. So the base
  fields are computed by ONE shared function from the returned point: `stationarity` = inf-norm of the
  declared Lagrangian gradient with `lambda_e`, `lambda_i`, `z`; `feasibility_e` = inf-norm of `ce`;
  `feasibility_i` = inf-norm of the positive part of the declared inequality and bound violations;
  `complementarity` = inf-norm of the declared inequality and bound products; `ce`, `ci` the declared
  residual vectors at the returned point (populated on EVERY exit family — budget-best and restoration
  exits included; the last history row is not the source). Each engine's OWN convergence measurements
  are retained unchanged, by their old names, on its engine result (`IpmResult::kkt_inf`, `barr_inf`,
  `econ_inf`, `icon_inf`; `SqpResult::sqp_stationarity`, `sqp_feasibility`, `sqp_complementarity`,
  and `kkt_residual` — kept, since `SqpIterate` and the printed table still carry it). The shared
  diagnostics are a reporting ADDITION, pinned by a test that computes them independently; no
  convergence test changes.
- `IpmResult : SolveResult` adds, field by field from today's `SolveResult` (astra's audit, all
  placed): `fixed_variable_treatment`; the internal fixing-row tails of the equality blocks
  (`internal_fixed_ce`, `internal_fixed_lambda_e` — today's equality vectors carry them; the base
  `ce`/`lambda_e` are declared rows only, and `z` for an eliminated coordinate is the fixing row's
  multiplier, documented); the four engine measurements above; the six timings (`total_time`,
  `pre_time`, `func_time`, `kkt_time`, `print_time`, `solver_init_time`, with `misc_time()` as today
  and `solver_init_time` explicitly OUTSIDE the phase timer); `factor_mem`, `factor_flops` (the
  last factorization's statistics); `soc_steps_taken`, `watchdog_activations`,
  `recovery_depth_histogram`; the eleven `last_*` fields with their sentinels and per-call scope
  unchanged (`last_funnel_width`, `last_filter_size`, `last_filter_resets`, `last_monotone_switches`,
  `last_monotone_iters`, `last_feas_rest_entries`, `last_feas_rest_iters`, `last_prox_reg_primal`,
  `last_prox_reg_dual`, `last_eval_exception`, `last_kkt_info`); the per-phase reports; and the
  factorization introspection as a SNAPSHOT: `kkt_analysis_count` (lifetime total at the time of the
  result, named `kkt_analyses_total`) and `kkt_analyses_this_call` (the delta), `kkt_factor_counters`
  (the counters struct as of the result), `eval_error_log`. `kkt_pattern_is_analyzed()` is a LIVE
  question and stays a const member on `IpmSolver`. `reset_accumulators()` is retired (a result is a
  value). `wall_seconds` = today's `total_time`; the measurement boundary (public `solve` entry to
  return) is stated on both engines.
- `SqpResult : SolveResult` adds `history`, `counters`, `scaling`, `infeasibility_certified`, the
  three engine measurements + `kkt_residual`, and the engine-native `warm_start` (today's
  `SqpSolution::warm_start`, an `SqpWarmStart`, §2.4 — kept, because the hot chain closes through it).
- **`export_warm_start()` on the result** carries its own metadata: the declaration stamp and (IPM)
  the polish payload's bound duals and barrier state are SNAPSHOTTED into the result at solve exit while
  the model and workspace are valid, exactly as today's capture code does before later model changes.
  Export after a solve that produced no usable point (`kNumericalError` before the first iterate)
  returns `std::nullopt` — the signature is `std::optional<WarmStartData> export_warm_start() const`;
  the `std::logic_error` "no completed solve" and its pin go. Edits to the public result fields do not
  affect the export (it reads the snapshot), documented.

### 2.4 Warm start — one protocol, two identities, one labelled SQP-only entry
- The shared form on both: `solve(model, x0, const WarmStartData &warm, budget)`. The staging calls
  (`stage_warm_start`, `clear_staged_warm_start`) and the IPM's `set_initial_multipliers` /
  `clear_initial_multipliers` go.
- **The rule, stated once for both engines: identity mismatch REFUSES; pattern mismatch DEGRADES;
  value defects DEGRADE.** Identity = the `DeclarationKey` stamp (`structure_key_`) against the bound
  model's declaration key: block lengths first, then the stamp, both `std::invalid_argument` at solve
  entry — the IPM's rule, and already the SQP's for a staged payload. Pattern = the SQP's structure hash
  of the assembled QP matrices: a mismatch resolves kSeeded with values contributed and state refused —
  that degrade IS the ladder (mesh transfer onto a re-partitioned grid, continuation across a pattern
  change, any hand-off from the IPM whose hash is 0). Value defects = the SQP's seeded clamp band
  (`kSeededDualClampTol`, a negative `lambda_i` within 1e-6 zeroed, anything more negative degrades the
  object to kCold) and the IPM's seeded floor/cap — they stay degrades, counted as today.
- **Three constants, three policies, one header.** `kSeededIqMultFloor = 1e-8` (IPM floor: seeded
  inequality multipliers pushed up to stay interior), `kSeededMultInitMax = 1e6` (IPM cap),
  `kSeededDualClampTol = 1e-6` (SQP sign band). They move to `warmstart/seeding.h` together; their
  values and policies are NOT unified — unifying them changes trajectories.
- Checks at the same points on both: finiteness and payload self-consistency when the payload is handed
  over (the SQP's ingest-time finiteness predicate stays the gate for every route); lengths and stamp at
  solve entry.
- **Multipliers-only seed, specified:** a `WarmStartData` whose `primal_` is EMPTY (size 0) is the
  multipliers-only form; `x0` is then the start; `eq_lmults_`/`iq_lmults_` must match the declared
  row counts and `bound_lmults_` must be empty or match `x0`'s size; finiteness applies; the stamp is
  required; under a `start_level` ceiling of kCold the seed is ignored and counted. This replaces the
  IPM's `set_initial_multipliers` path with its clamps applied, and is a small SQP code change (today
  an empty primal fails the plausibility check and resolves kCold).
- **The labelled SQP-only entry** (the lane's amendment 2, accepted): `SqpResult solve(ClaimStreamSource
  &, const Vec &x0, const SqpWarmStart &warm, SolveBudget = {})`, with `SqpWarmStart` (today's
  `detail/warmstart/warm_start.h::WarmStart`) promoted to `include/hven/warmstart/sqp_warm_start.h`.
  It is the exact counterpart of the IPM-only `set_kkt_hook` (§2.5): one engine-only extension per
  engine, labelled as such in the header and the guide, nothing invented for the other side. Without it
  kWarm and kHot are unreachable from the public surface (the payload caps at kSeeded by construction;
  the hot handle is a process-local `shared_ptr` that is never serialized) and the 70 test/bench call
  sites, the U0 corpus's own warm arm, `bench_scale`'s hot chain and `run_continuation` have no route —
  the replay proofs presuppose it. Continuation and mesh transfer keep using it (rename only).
  `to_sqp_warm_start` stays public in `warmstart/` (it is the crossover from the payload to the native
  type and continuation callers use it); `from_interior_point` stays where it is.
- The IPM polish extension (`hven.ipm.polish.v1`) stays as the one serialized extension. A lossless
  serialized SQP-state envelope (astra's alternative) is REGISTERED for M7 with the model-contract task,
  not built here: the labelled entry closes the reachability gap in-process, which is what every
  current consumer needs.
- **The kIpm-mode cold grade — RULED by the owner, 2026-09-07: REFUSE in every mode.** In `QpMode::kIpm`
  a staged payload's stamp or dimension mismatch was the COLD grade, not a refusal, by M5 plan ruling 4 /
  spec 5.4 (`sqp_driver.cpp:1774-1783`). That ruling is RETIRED for this case: a payload that does not
  match the declaration is a caller error in any mode, on both engines. The pin names the retired ruling
  and the guide entry records it.

### 2.5 One iteration callback, one labelled IPM-only hook
- On both: `set_iteration_callback(IterationCallback)` / `clear_iteration_callback()`;
  `IterationCallback = std::function<CallbackAction(const IterationEvent &)>`; `CallbackAction {
  kContinue, kStop }`. Callback exceptions propagate out of `solve` after the engine's ordinary cleanup
  (no state left half-updated: the SQP fires from a site that owns no half-written state; the IPM
  fires after the iterate is committed).
- `IterationEvent`, one view for both, ALL in declared space and CALLER units: `iteration` (the
  engine's own count — SQP major index, IPM per-phase iterate index — plus `phase` on the IPM),
  `std::optional<int> depth` (SQP restoration nesting; absent on the IPM, matching the trace), `f`,
  the three shared diagnostics of §2.3 computed at the event point, `step_norm` (the accepted step's
  inf-norm; on the IPM the primal block of `alpha * DXSL`), `std::optional<double> radius` (SQP),
  `std::optional<double> mu` (IPM barrier parameter), read-only `x`, `lambda_e`, `lambda_i`, `z`
  (views valid for the callback's duration only, documented), `elapsed_seconds`. The IPM's late
  callback hands out the REDUCED space today; the event's vectors are expanded by the workspace's
  scatter, equality rows sliced to declared rows, and the fixed-coordinate dual semantics of §2.3 apply.
- **Where it fires.** SQP: from `push_history`, immediately after the trace emit and before the push —
  the one emit site with its ten callers (T6.c) — so trace, history and callback are the same rows in the
  same units at one site and the `rows_pushed` identity proves nothing else fires it; the multipliers
  and `z` have the scaling map applied (they are scaled inside the loop and mapped only in `finish`
  today). The nested restoration driver FORWARDS the callback with `depth` set (a consumer that wired
  an abort expects it to reach every iteration; restoration can run to `max_iter - spent` majors). IPM:
  at BOTH of today's late-callback sites — the ordinary post-step site and the pre-factorization
  convergence early exit — as the trace does; the ordinary site fires AFTER the iterate commit (`XSL
  += alpha * DXSL`), which is a change from today's before-commit call and is pinned; the return value
  is read only on a continuing row (a stop returned at a terminal row is moot by construction).
- **`kStop`.** SQP: honoured beside the probe budget in the exit conjunction, routed through the (c)
  finish fold with `kInterrupted`, precedence `converged > interrupted > probe-exhausted > max_iter`;
  an interrupt takes the ORDINARY exit (the last iterate, as the probe budget does), never the
  budget-best. IPM: honoured at the ordinary site; ends the current phase with `kInterrupted` at the
  current point and short-circuits the remaining phases (§2.2); cleanup, trace end event and ledger
  record all run. Today the IPM ignores the late callback's integer return at both sites, so `kStop`
  is a behaviour change on both engines and is pinned across phases and restoration.
- The IPM's early hook stays as the labelled IPM-only extension `set_kkt_hook(KktHook)` /
  `clear_kkt_hook()`, semantics unchanged from W5 T2 (read-only vectors, value-mutable KKT, structural
  mutation refused). Nothing equivalent is invented for the SQP.

### 2.6 Instrumentation, printing, threading, the jet wrapper
- `attach_trace(TraceSink *)` already matches. `attach_ledger(Ledger *, std::string label_prefix)`
  comes to the IPM with an `IpmSolveRecord` and `Ledger::ipm_records()` / `ipm_summary_table()`.
- **Printing.** The IPM's console table becomes a `ConsoleTraceSink` in `drivers/`, attached by the
  solver when printing is on, fanned out beside the user's sink (both receive every event; attaching
  the console never displaces a user sink). astra's audit of what the table needs beyond today's
  events, all supplied: the acceptable tolerances and the layout width go on the begin event; the
  previous row (for colouring) is sink state; the restoration-exit row that today prints without
  passing either iter site gets its own emit; the sink's formatting configuration is immutable per
  solve. **Print level keeps the IPM's convention, translated explicitly:** today 0 prints everything
  and 3+ is silent; `common.print_level` keeps those numbers and that meaning on BOTH engines (the SQP
  gains printing at the same levels, its table being today's `format_iteration_table`). The proof is a
  byte-pin of the rendered table from INJECTED records (wide and narrow layouts, the colour thresholds),
  never of measured timing values. `print_header()` and the fmt calls in the IPM loop go; `wide_console`
  becomes a sink option.
- **Threading.** `common.threads` on both. SQP default `0` = "leave the backend as it is" — today's
  configured value (`num_threads = 0`, the process-wide `MKL_NUM_THREADS` pin being the reproducibility
  mechanism); any numeric default would override the pin and move every MKL-touching pin on an unpinned
  box. When non-zero on the SQP it must reach EVERY factor path: the walk/SSN sessions in `QpEngine`
  including its temporary and fallback factors, `SsnEngine`'s persistent factor, `IpqpEngine`'s KKT
  factor, and nested restoration solves — applied at each `SymmetricFactor` backend call through its
  owner. IPM default stays `min(HVEN_DEFAULT_QP_THREADS, core count)`. Proof of neutrality is replay
  0/75 at `threads = 0` under the env pin (identity by construction — the value the factors receive is
  unchanged) plus a propagation test that observes the backend configuration at every tier at a
  non-zero count; a counter check at threads=1 proves nothing (the known sensitivity is float
  residuals). **CNR stays IPM-only in T8**: it is process-global, requires nested-dissection ordering
  and is refused on Accelerate; two solvers in one process would fight over one MKL. The IPM's
  evaluation-pool thread count is NOT `common.threads` (the aggregate contract says engine threading
  never routes through the model); it stays where the program sets it. Accelerate values UNOBSERVED.
- **The legacy `NLPSolver` jet wrapper is RETIRED IN GROUP 1, not group 2** (astra): it is not a rename
  — it performs lazy triplet-model transcription, starting-multiplier staging, result copy-back, default
  partition/thread setup and jet-worker preparation. Each responsibility gets a named replacement in
  the commit that deletes it: transcription → `NonLinearProgram`'s own adopt path; multiplier staging →
  the multipliers-only seed (§2.4); result copy-back → the value result; partition/thread setup → the
  program's `negotiate_partition_count` / `set_evaluation_threads`; the jet modes → `IpmOptions::phases`.
  Its 19 users migrate in that commit.

### 2.7 Proof for group 1
Every behaviour change is NAMED and PINNED; astra was right that there are more than three. The list:
(1) SQP refuses an identity-mismatched payload in every mode (§2.4, ruled), (2) `kInterrupted`
on both engines, (3) the IPM's ordinary callback site fires after the commit, (4) the SQP thread count

out of NOTCONVERGED, (7) the shared diagnostics added to every result, (8) `set_options` rebuilding the
SQP engines (hot handles degrade), (9) the restoration-exit print row emitted as an event. Everything
else is identity: U0 replay 0/75 on all three SQP arms AND a top-level IPM leg (astra: the corpus's
`ipm` arm is the SQP's IPQP tier — a representative top-level `InteriorPointSolver` replay set,
partitioned and fixed-variable workloads included, is added to the harness in the first commit and is
the IPM's identity proof for every later commit), the HS pins, both suites, the golden rig,
per-symbol identity with NAMED exceptions per commit (the surface functions each commit changes are
listed by name; "all surface functions" is not an exception class), install smoke and export contract
after every commit touching a public header (the smoke extended with a generic installed consumer
compiled against BOTH solvers through the shared shape), the console-table byte-pin, the full
warm-level matrix (cold/seeded/warm/hot × payload/native × match/pattern-mismatch/identity-mismatch),
