## 1. The problem, in one paragraph

The two engines were migrated from two projects and joined by warm-start currency. Today nothing on
their public surfaces is spelled the same: five phase-named IPM entries returning a bare vector against
one `solve` returning a value; fifty validated setters on a mutable settings object against ctor-frozen
options with no accessor; two status enums with the same integer shape and different names and
namespaces; two result structs, two counter models, two iterate-row types, a residual vocabulary that
collides under shared names; one warm-start payload with two protocols; a per-iteration callback on
one side only; and, underneath, two model contracts. The last is deferred (§6); everything else is T8.

### 2.1 Classes, lifetime, options
- Both classes in `hven::solvers`. **Neither is movable or copyable in T8.** The IPM and
  `KktFactorization` suppress movement deliberately; the SQP holds `QpEngine` by value with backend
  sessions inside and declares no move. Movability is a separate design and is registered (§5).
  tycho's `clone_prototype` keeps returning `unique_ptr` for both.
- `IpmOptions` and `SqpOptions`: aggregate structs, bare `snake_case` fields (the IPM's trailing
  underscores go). Each embeds one `CommonOptions common` for: `threads` (§2.6), `print_level`
  (§2.6), `start_level`. Engine-specific stays engine-specific: the SQP's nested `QpOptions` /
  `IpqpOptions`; the IPM's barrier, acceptance, inertia, restoration, watchdog, return-best,
  fixed-variable-treatment and sparse-backend knobs. CNR (`cnr_mode`) stays IPM-only in T8 (§2.6).
- Validation: one free `validate(const IpmOptions &)` / `validate(const SqpOptions &)` throwing
  `std::invalid_argument`, run at construction and at replacement; today's `Settings::validate()` and
  `validate_sqp_options` become these.
- Construction: `explicit IpmSolver(IpmOptions = {})`, `explicit SqpSolver(SqpOptions = {})`. `const
  XOptions &options() const` on both. **`void set_options(XOptions)` on both, legal between solves
  only (`std::logic_error` during a solve; a flag held for the whole public `solve`) and
  TRANSACTIONAL:** validate first; then construct the replacement engines/sessions into temporaries; only
  on success swap them in and adopt the options. A throw at any point (validation OR construction) leaves
  the previous options and engines in force and the solver usable. Trace and ledger attachments survive
  replacement on both.
- **Hot-handle policy on SQP option replacement (astra amendment 2, the lane's (d)):** `HotState` owns
  its backend state through a `shared_ptr`, survives its producer and CAN be adopted by a different
  `QpEngine`, so a rebuilt engine does NOT automatically lose reuse. The rule is therefore EXPLICIT
  (**v3.1, settler amendment at the T8.3 pre-read, 2026-09-08:** the key is the producing engine's OPTIONS
  FINGERPRINT, not a per-instance session id — the lane showed that at b43580f cross-engine adoption is the
  hot handle's ONLY use (`run()` adopts a handle only when its own `border_valid_` is false, so a driver's
  own second solve is kHot through its own cache), and a per-instance key would refuse every cross-engine
  adoption, flip five M5 pins and make `WarmStart::hot` dead on the SQP — a currency change this design
  never intended): `HotState` carries `engine_options_hash`, a field-wise hash of the producing engine's
  `QpOptions` PLUS the thread count in force; a hot handle whose fingerprint is not the adopting engine's
  is REFUSED for hot reuse — it resolves kWarm by construction (values and working set still contribute;
  the factor is rebuilt). A rebuilt engine with changed QP or thread options therefore refuses the old
  handle; an identical-options replacement adopts (same factor object, same options); a fresh driver
  with the same options adopts, as today. Replacement with identical options ALSO rebuilds (one rule, no
  "unchanged" fast path). What (a)–(e) fingerprint is the PROBLEM and the FACTOR OBJECT, never the engine
  options the K0 was built under — this closes that hole. Pinned: identical options (kHot), changed QP
  options (kWarm), changed thread count (kWarm — hashed from T8.3 although the count is carried, not
  applied, until T8.8), producer destroyed (the M5 pin `HotReusesFactorization` stands), failed
  replacement (the same driver's next solve kHot, `k0_reused == 1`).
- The IPM's ~50 validated `set_*` methods, its four static `strto_*` parsers and its six string-taking
  setter overloads GO. Presets become free functions returning a full value: `IpmOptions
  ipm_preset(std::string_view)` (the existing table) and `SqpOptions sqp_preset(std::string_view)`
  ("default" only until M8's labeled configs).

### 2.2 The solve family
- IPM: `IpmResult solve(NonLinearProgram &model, const Vec &x0, SolveBudget = {})` and `solve(model,
  x0, const WarmStartData &warm, SolveBudget = {})`. **SQP: `SqpResult solve(NlpModelAggregate &model,
  …)`** with the same two forms PLUS the labelled SQP-only entry `solve(model, x0, const SqpWarmStart
  &warm, SolveBudget = {})` (§2.4). The SQP keeps its CONCRETE aggregate type in T8 (astra amendment 1,
  the lane's (a)): restoration builds its feasibility model from the concrete model and the elastic seed
  clamps through it — exactly the work §6 defers — so a `ClaimStreamSource &` entry today would have to
  downcast and refuse every other provider. Both engines widen in M7 (§0 item 3). The SQP's `const
  NlpModel &` convenience overloads (a bridge per call) stay.
- The model is borrowed for the call on both; the IPM's `set_nlp` / `release`, the `shared_ptr`
  binding and the model-taking constructor go. Cross-solve reuse on the IPM (symbolic analysis, pattern
  hash, partition setup) is keyed on a **lifetime-safe identity token** — the program's
  `model_structure_key()` plus its structure epoch plus the fixed-variable treatment in force — never a
  retained address: a different key, a bumped epoch or a changed treatment re-analyses; the same triple
  does not. **Live introspection (astra amendment 6):** `kkt_pattern_is_analyzed()` cannot stay a
  no-argument query once the model is borrowed only during the call (it dereferences the retained
  model today). It becomes `bool kkt_pattern_is_analyzed(const NonLinearProgram &model) const` — true iff
  the workspace's current analysis token matches that program's — and the snapshot fields on
  `IpmResult` (§2.3) answer the after-the-fact questions. No raw model pointer outlives `solve`.
- **The IPM's five phase-named entries become `IpmOptions::phases`**, a sequence of `IpmPhase`
  (`kOptimize`, `kSolve`), default `{kOptimize}`. The rule for ANY sequence, of which the five legacy
  names are documented instances: phases run in order; a `kSolve` that FOLLOWS a `kOptimize` runs only
  if that optimize phase did not converge (today's conditional trailing solve, generalised: the
  condition is evaluated on the immediately preceding phase); the first optimality phase installs the
  seeded multipliers; every phase re-initialises per today's inter-phase rules; a fatal status
  (`kNumericalError`, `kDiverging`, `kInterrupted`) short-circuits the sequence; the empty sequence is
  `invalid_argument`. The `result()` accessor goes.
- **`SolveBudget`** — `{Index minor_budget = 0 /*unlimited*/; Index max_iterations = 0 /*engine
  option*/; }`. SQP: `minor_budget` is today's probe budget with its accounting unchanged (it charges
  SSN/IPQP work, not only walk minors); when the probe budget is exhausted the solve reports
  **`kMaxIter` at the current point, exactly as today** (astra amendment 4: `kBudgetExhausted` belongs
  to the separate budget-BEST exit under `budget_mode`, unchanged). `max_iterations`, when non-zero,
  gives an EFFECTIVE cap `min(budget, opts.max_iter)` for the top-level solve, and restoration is
  budgeted from that effective cap (`effective - spent`, the lane's (e)), so it cannot spend past the
  caller's cap. IPM: `max_iterations`, when non-zero, caps EACH phase at `min(budget,
  opts.max_iters)`; `minor_budget` is ignored and documented so. A partial phase sequence returns the
  last phase's result.
- **`iterations` on the result, defined:** SQP = `counters.major_iters` of the top-level solve (nested
  restoration majors are NOT added; they are in `counters`); IPM = the sum over the phases run of each
  phase's iterate count (today's `iter_num_` semantics per phase), with the per-phase counts on the phase
  reports.

### 2.3 Status and result
- `SolveStatus` in `hven::solvers`: `kOptimal`, `kAcceptable`, `kMaxIter`, `kInfeasible`,
  `kStalled`, `kDiverging`, `kNumericalError`, `kBudgetExhausted`, `kInterrupted`. Nine values: the
  IPM's `NOTCONVERGED` covers both the iteration cap and two pre-cap exits — the locally-infeasible
  restoration return (`interior_point_solver.cpp:2329`) and `exit_stage_stalled` (`:3171`) — so
  NOTCONVERGED maps to `kMaxIter` when the cap was hit and to `kStalled` at those two sites; **a
  stronger verdict the convergence checker already holds (converged/acceptable) is preserved over the
  stall, and a simultaneous stall-and-cap reports `kStalled`** (pinned). Rest of the mapping — IPM:
  CONVERGED→kOptimal, ACCEPTABLE→kAcceptable, DIVERGING→kDiverging, SINGULAR_KKT→kNumericalError.
  SQP: identity on its five. Reachability, documented per engine: the IPM cannot report kInfeasible or
  kBudgetExhausted; the SQP cannot report kAcceptable, kStalled or kDiverging; NEITHER reports
  kInterrupted today — it is new (§2.5). SQP `kInfeasible` is not necessarily certified
  (`SqpResult::infeasibility_certified`). **Reachability qualifier (T8.2 close, the lane's M1):** the
  IPM's stalled exit (`kStageStalled` → `kStalled`) is demonstrated reachable only with divergence
  detection lifted (`div_tols` 1e300 on a fixture whose violation spikes to ~1e40 and decays for ~55
  elevated iterations); at the default thresholds the same fixture reports DIVERGING after four
  iterations (pinned beside the stall pin). Default-threshold reachability of the stall exit is
  UNDEMONSTRATED. The cap reason is phase-local and stored at both cap doors without reading the
  per-call verdict; a converge-on-the-cap phase reads `kNone`. The per-call `converge_flag_` vs
  per-phase reason lifetime mismatch (a later phase exhausting after an earlier one converged reports
  the earlier verdict) is a PRE-EXISTING defect registered for T8.4's per-phase results.
- `const char *to_string(SolveStatus)`. `int severity(SolveStatus)` for ALL nine (kOptimal <
  kAcceptable < kInterrupted < kMaxIter < kBudgetExhausted < kStalled < kInfeasible < kDiverging <
  kNumericalError) — a reporting order only; phase termination is §2.2's short-circuit rule.
  `hven::ConvergenceFlags` and `hven::solvers::SqpStatus` go.
- `SolveResult`, a NON-POLYMORPHIC base struct (aggregate inheritance; `r.status`; no virtuals; never
  deleted through a base pointer; slicing value-preserving for the base fields). Fields, ALL in
  declared space and CALLER units: `status`, `x`, `lambda_e`, `lambda_i`, `z`, `f`, `stationarity`,
  `feasibility_e`, `feasibility_i`, `complementarity`, `ce`, `ci`, `iterations`, `wall_seconds`, and
  `std::optional<WarmStartData> export_warm_start() const`.
- **Shared diagnostics: defined once, over the declared NLP, in caller units, from a STASHED
  evaluation — never a fresh one.** The engines' own convergence measurements stay by their old names on
  the engine results (`IpmResult::kkt_inf`, `barr_inf`, `econ_inf`, `icon_inf`;
  `SqpResult::sqp_stationarity`, `sqp_feasibility`, `sqp_complementarity`, `kkt_residual` — kept, since
  `SqpIterate` and the printed table carry it). The shared fields are a reporting ADDITION computed by
  one function in `solve_result.cpp` from `(x, lambda_e, lambda_i, z, f, ce, ci, grad, Je, Ji)` at the
  RETURNED point, where that evaluation is the one the engine already holds: the SQP stashes the
  evaluation bundle (`NlpEval`: gradient, ce, ci, Jacobians) alongside `BudgetBest` and at the
  restoration return (memory, no work — the lane's (b): a fresh evaluation would move `evals_full` and
  fail the U0 identity proof by construction); the IPM uses its last full evaluation at the returned
  iterate. Where no finite evaluation exists at the returned point — the SQP's non-finite start exit,
  an IPM `kNumericalError` before the first iterate, a restoration return whose last evaluation was of
  the feasibility model — every shared diagnostic is **NaN = unmeasured** and `ce`/`ci` are empty,
  documented (absent is never zero-filled). Definitions: `stationarity` = inf-norm of `grad f + Jeᵀ
  lambda_e + Jiᵀ lambda_i − z` over DECLARED coordinates that were evaluated (§ fixed coordinates
  below); `feasibility_e` = inf-norm of `ce`; `feasibility_i` = inf-norm of the positive part of the
  declared inequality and bound violations; `complementarity` = inf-norm over the declared inequality
  products `lambda_i ∘ ci` and the CANONICAL bound products `max(z,0) ∘ (x − l)` and `max(−z,0) ∘ (u −
  x)` (astra amendment 3: a signed `z` cannot recover two separate prices at a two-sided bound, so the
  shared diagnostic is the canonical split, stated; the IPM's own two-price complementarity stays in
  `barr_inf`). Pinned by a test that computes them independently; no convergence test changes.
- **Fixed coordinates on the IPM (astra amendment 3, corrected):** under `MakeParameter` an eliminated
  variable has NO fixing row; its `z` entry is 0 and its stationarity coordinate is EXCLUDED from the
  inf-norm (the reduced candidate-gradient path returns 0 there, which is not a measurement), documented.
  Under `MakeConstraint` the variable remains with a fixing row `x − value = 0` of Jacobian `+1`; that
  row is removed from the declared equality block and its multiplier enters the bound dual as **`z =
  −lambda_fix`** (stationarity `grad f + Jᵀ lambda − z = 0`), so the declared-space stationarity closes.
  The internal fixing rows are reported on `IpmResult` (`internal_fixed_ce`, `internal_fixed_lambda_e`).
- `IpmResult : SolveResult` adds, field by field from today's `SolveResult` (all placed):
  `fixed_variable_treatment`; the two internal fixing-row vectors; the four engine measurements; the six
  timings (`total_time`, `pre_time`, `func_time`, `kkt_time`, `print_time`, `solver_init_time`, with
  `misc_time()` as today and `solver_init_time` OUTSIDE the phase timer — **these keep TODAY's
  boundaries exactly**; `wall_seconds` is a NEW common measurement, §2.3 last bullet); `factor_mem`,
  `factor_flops`; `soc_steps_taken`, `watchdog_activations`, `recovery_depth_histogram`; the eleven
  `last_*` fields with their sentinels and per-call scope unchanged; the per-phase reports (each with its
  iterate count and status); the factorization SNAPSHOT: `kkt_analyses_total` (lifetime, at the time of
  the result), `kkt_analyses_this_call`, `kkt_factor_counters`, `eval_error_log`.
  `reset_accumulators()` is retired.
- `SqpResult : SolveResult` adds `history`, `counters`, `scaling`, `infeasibility_certified`, the three
  engine measurements + `kkt_residual`, and the engine-native `warm_start` (an `SqpWarmStart`, §2.4).
- **`wall_seconds` (astra amendment 8, timing):** a NEW common measurement with ONE boundary on both
  engines — from public `solve` entry (after argument validation) to return, INCLUDING seam/warm setup,
  final reporting and the export snapshot. It is NOT today's `total_time` (which stops before final
  reporting/export) nor today's SQP `wall_seconds` (which times `solve_impl` after setup); both old
  measurements are preserved under their old names (`IpmResult::total_time`, `SqpResult::solve_impl_seconds`
  — renamed from today's `wall_seconds` so the name is not reused with a different meaning). The change
  is named in §2.7 and in the guide.
- **`export_warm_start()` on the result** carries its own metadata: the declaration stamp and (IPM) the
  polish payload's bound duals and barrier state are SNAPSHOTTED at solve exit while the model and
  workspace are valid. **When it is `nullopt`, per engine (the lane's (h)):** IPM — a `kNumericalError`
  before the first iterate (no usable point). SQP — NEVER: every SQP exit, the non-finite start included,
  returns a finite `x0` with zero multipliers and a valid stamp, so the SQP's export is always present
  (the optional exists for the IPM case and for the shape; this is not a behaviour change on the SQP).
  The `std::logic_error` "no completed solve" and its pin go. Edits to public result fields do not affect
  the export.

### 2.4 Warm start — one protocol, two identities, one labelled SQP-only entry
- The shared form on both: `solve(model, x0, const WarmStartData &warm, budget)`. The staging calls and
  the IPM's `set_initial_multipliers` / `clear_initial_multipliers` go.
- **The rule for the PAYLOAD form, on both engines: identity mismatch REFUSES; pattern mismatch
  DEGRADES; value defects DEGRADE.** Identity = the `DeclarationKey` stamp (`structure_key_`) against
  the bound model's declaration key: block lengths first, then the stamp, both `std::invalid_argument`
  at solve entry — in EVERY SQP mode (§0 item 4; M5 ruling 4 retired for this case; the pin names it).
  Pattern = the SQP's structure hash of the assembled QP matrices: a payload always carries hash 0 and
  resolves at most kSeeded — that is the ladder. Value defects = the SQP's seeded clamp band
  (`kSeededDualClampTol`: a negative `lambda_i` within 1e-6 zeroed, anything more negative degrades the
  object to kCold) and the IPM's seeded floor/cap — degrades, counted as today.
- **The NATIVE route (`SqpWarmStart`) keeps ITS OWN validation, unchanged (astra amendment 2):** it
  carries no declaration stamp, so nothing is "refused for identity"; `valid`, the five size checks and
  the ingest-time finiteness predicate resolve kCold as today; a structure-hash mismatch resolves
  kSeeded; a match resolves kWarm; a match plus a hot handle whose engine-options fingerprint is the adopting
  engine's (§2.1 v3.1)
  resolves kHot subject to the backend reuse checks. The warm matrix in §2.7 distinguishes the two
  routes; continuation and mesh transfer are native-route callers and are unchanged.
- **Three constants, three policies, one header (`warmstart/seeding.h`):** `kSeededIqMultFloor = 1e-8`
  (IPM floor), `kSeededMultInitMax = 1e6` (IPM cap), `kSeededDualClampTol = 1e-6` (SQP sign band).
  Values and policies NOT unified.
- Checks at the same points on both: finiteness and payload self-consistency when the payload is handed
  over; lengths and stamp at solve entry.
- **Multipliers-only seed, specified (the lane's (g), astra amendment 7):** a `WarmStartData` whose
  `primal_` is EMPTY is the multipliers-only form; `x0` is then the start. Hand-over rule amended to:
  `primal_` and `bound_lmults_` are EITHER both empty OR both of one length (today's "one length" rule
  with the empty case added); `eq_lmults_`/`iq_lmults_` must match the declared row counts; finiteness
  applies; the stamp is required. Omitted blocks mean "no seed for that block" — never zero. **The SQP
  never ingests `z` from any seed** (today's rule, stated). **A polish extension on a multipliers-only
  payload is IGNORED** (its bound duals and barrier state are point-dependent and the point is `x0`,
  not the exporter's) and counted. Under a `start_level` ceiling of kCold the seed is ignored and
  counted. This replaces the IPM's `set_initial_multipliers` path with its clamps applied, and is a small
  SQP code change (today an empty primal fails the plausibility check and resolves kCold) — §2.7 (5).
- **The labelled SQP-only entry:** `SqpResult solve(NlpModelAggregate &, const Vec &x0, const
  SqpWarmStart &warm, SolveBudget = {})`, with `SqpWarmStart` (today's
  `detail/warmstart/warm_start.h::WarmStart`) promoted to `include/hven/warmstart/sqp_warm_start.h`; it
  holds a `WorkingSet` by value, so `detail/qp/working_set.h` becomes an installed dependency and the
  export contract is told to accept it (the lane's (f); `HotState` stays a forward declaration). The
  exact counterpart of the IPM-only `set_kkt_hook` (§2.5): one engine-only extension per engine,
  labelled in the header and the guide. Without it kWarm and kHot are unreachable from the public
  surface (the payload caps at kSeeded; the hot handle is process-local and never serialized) and the 70
  test/bench call sites, the U0 corpus's warm arm, `bench_scale`'s hot chain and `run_continuation` have
  no route. `to_sqp_warm_start` and `from_interior_point` stay public in `warmstart/`.
- The IPM polish extension stays the one serialized extension. A lossless serialized SQP-state envelope
  is REGISTERED for M7 (§6), not built here.

### 2.5 One iteration callback, one labelled IPM-only hook
- On both: `set_iteration_callback(IterationCallback)` / `clear_iteration_callback()`;
  `IterationCallback = std::function<CallbackAction(const IterationEvent &)>`; `CallbackAction {
  kContinue, kStop }`.
- **Exceptions from the callback propagate out of `solve`.** SQP: the solve-begin/solve-end trace pair
  and the ledger record are explicitly NON-RAII (fix-round ruling R1 at W2), so a throwing callback
  produces NO end event and NO ledger record, exactly as any other throw out of the loop does today —
  stated, not changed (the lane's (c)). IPM: likewise no end event. The solver remains usable for the
  next solve on both (pinned).
- `IterationEvent`, one view for both, ALL in declared space and CALLER units: `iteration` (SQP major
  index; IPM per-phase iterate index) and `std::optional<int> phase` (IPM), `std::optional<int> depth`
  (SQP restoration nesting), `f`, the FOUR shared diagnostics of §2.3 (`stationarity`,
  `feasibility_e`, `feasibility_i`, `complementarity`) at the event point from the engine's current
  evaluation (NaN where unmeasured), `step_norm` (SQP: `SqpIterate::step_norm`; IPM: inf-norm of the
  primal block of `alpha * DXSL`), `std::optional<double> radius` (SQP), `std::optional<double> mu`
  (IPM), read-only `x`, `lambda_e`, `lambda_i`, `z` (views valid for the callback's duration only),
  `elapsed_seconds`. On the IPM the vectors are expanded from the reduced space by the workspace's
  scatter, equality rows sliced to declared rows, fixed-coordinate duals per §2.3.
- **Where it fires, and what it observes (astra amendment 5):**
  SQP — from `push_history`, immediately after the trace emit and before the push, the one emit site
  with its ten callers (T6.c), so trace, history and callback are the same rows in the same units at one
  site and the `rows_pushed` identity proves nothing else fires it; multipliers and `z` have the scaling
  map applied. The event describes the ROW being pushed (the accepted iterate of that major, as the
  history does), not the pending commit. The nested restoration driver FORWARDS the callback with
  `depth` set.
  IPM — two dispatches, CONTINUING and TERMINAL, so no callback is lost and no trajectory moves: on a
  continuing iterate the callback fires AFTER the commit `XSL += alpha * DXSL` and observes the committed
  point (x, duals, objective and diagnostics all of that point, after bound/elastic commits); on the
  ordinary terminal branch (which breaks BEFORE the commit today) the callback fires at the point the
  phase returns, with the same coherence rule; the pre-factorization convergence early exit is a terminal
  dispatch too. Both dispatches fire where the trace fires today. The commit order itself is unchanged.
- **`kStop` — precedence and the returned point.** Read only on a CONTINUING dispatch; on a terminal
  dispatch of a PHASE or a NESTED solve the return value is still read, because that terminal is not
  terminal for the public call: on the IPM a stop at a phase's terminal row short-circuits the remaining
  phases; on the SQP a stop inside restoration LATCHES `interrupted` before any outer resume logic runs,
  so the parent major exits `kInterrupted` at the point the parent holds when restoration returns (the
  restoration's returned point, as a restoration return does today). SQP precedence in the exit
  conjunction: `converged > interrupted > probe-exhausted > max_iter`; an interrupt takes the ORDINARY
  exit at the CURRENT point (as the probe budget does), never the budget-best; routed through the (c)
  finish fold with `kInterrupted`. IPM: `kInterrupted` at the current point, cleanup, trace end event and
  ledger record all run. Today the IPM ignores the late callback's integer return at both sites, so
  `kStop` is a behaviour change on both engines and is pinned across continuing rows, terminal rows,
  phases and restoration.
- The IPM's early hook stays as the labelled IPM-only extension `set_kkt_hook(KktHook)` /
  `clear_kkt_hook()`, semantics unchanged from W5 T2. Nothing equivalent is invented for the SQP.
