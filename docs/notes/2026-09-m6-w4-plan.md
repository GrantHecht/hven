## §2. The serialization contract (FIXED here; the implementer implements)

1. One JSON object per line, `\n`-terminated, no pretty-printing, keys in the
   order the schema lists them; for the counters objects the order is the
   X-macro table's (byte-stable golden lines depend on it).
2. Envelope: `{"v":0,"ev":"<name>","seq":<n>,"depth":<d>, ...}` — `seq` and
   `depth` are SINK-OWNED, no event struct carries either: `seq` a monotone
   per-sink counter starting at 1, so a reader can prove it saw every line;
   `depth` per rule 4. `v` stays 0 for the whole window (rule 6).
3. Doubles: `fmt::format("{:.17g}", x)` — 17 significant digits, the spec's
   claim, made true by T1's round-trip pin, which includes −0.0 (prints `-0`)
   and a subnormal. Non-finite: the strings `"nan"`, `"inf"`, `"-inf"` (JSON
   has no NaN; a sentinel number would be a fabricated value); the doc types
   such a field as "number, or one of the three strings". Integers are
   64-bit (`Index`) and readers parse them as such — a JavaScript reader
   loses precision above 2^53, Python does not; bools as `true`/`false`.
4. `depth` is a counter the sink increments on `sqp.solve` begin and
   decrements on its end (0 for the top-level solve), so the nested
   restoration driver's pair, its rows and its IPQP events all read depth 1
   with no stack in the reader and no field on any event.
   **AMENDED at the T1 ledger (settler ruling, 2026-09-04, on the task review's
   I-2):** schema v0 carries NO vector-valued field anywhere. The five `Vec`
   members of `IpqpInfeasibilityEvidence` are excluded from `evidence` by THIS
   rule — not by amendment G, which is the IPM-side reason for the same fact —
   so `ipqp.escape` carries spec §6.3's least-infeasible point's two scalars
   (`least_infeasible_primal`, `least_infeasible_mu`), never the point.
5. ABSENCE IS `null`, never omitted and never zero-filled — CLAUDE.md §6.
   `std::optional` empty → `null`; the IPM's -1 "mode off" sentinel → `null`
   (the sentinel is a C++ convention, not a value).
6. v0 is FROZEN for the eight W1/W2 events from T1 onward: no field renamed,
   removed, or retyped, and their golden lines never move. The events W4
   adds (`sqp.major`, `sqp.solve`, `qp.mode`'s new strings, `ipm.*`) freeze
   at T5 when the doc lands; between T1 and T5 their golden lines are
   re-derived per task as DECLARED additive re-derivations. ADDITIVE changes
   — new events, new enum strings, new trailing fields — stay v0 until the
   schema has an external consumer (M7's first heuristic); the doc records
   each addition with its task. Anything non-additive is v1 and not this
   window's.
7. Wall-clock fields carry the suffix `_s` and are listed in the doc under
   "informational — never asserted" (CLAUDE.md §7). No W4 pin reads one.
8. Enum strings are the spec's (`"down|up"`, `"accept|inertia|stall|floor"`,
   …); new ones are lower-case snake, named in T2/T4.
9. Strings are escaped per RFC 8259 §7 (the `facts` field is opaque text).

## §3. The telemetry — definitions

(a) **`active_set_delta`** (bulk flip at the MAJOR level; the SSN counter is
the same idea one level down): the symmetric-difference count between this
major's QP active set and the previous major's — inequality rows
(`ineq_active`) plus bound sides (`bound_state`, a side that changed lower ↔
upper ↔ free counts once). First major: the count against the empty set
(everything active counts), stated in the doc. A rejected major still has a
QP solution and still reports; a row with `qp_solved == false` reports 0
and the previous set is carried unchanged.

(b) **`weak_active_rows`**: active inequality rows whose multiplier
satisfies `|lambda_i| <= kWeakActivityMargin * max(1, ‖lambda_i‖_inf)`;
**`near_active_rows`**: inactive rows whose QP slack satisfies
`s_i <= kWeakActivityMargin * max(1, ‖s‖_inf)`, `s = A_i p − b_i` computed
once from the `QpProblem` in scope (VERIFIED: nothing in the driver retains
it). `kWeakActivityMargin = 1e-6`, a `k` constant, NOT a setting — nothing
acts on it in W4. **These are a STRICT-COMPLEMENTARITY MAGNITUDE margin**
(`min(s_i, λ_i)` small in a relative sense) — the notion M7's weak-activity
heuristics need. **It is NOT the SSN's notion**: the SSN uncertain set is the
dimensionless KINK BAND `|(λ − s)/ρ| <= kSsnUncertainEnter = 0.1` with 3×
leave hysteresis (`ssn_engine.h:488-510`), which reads a PURE state at
`s = 0` for any `λ` and so never flags a small multiplier on an active row.
Both flag the tie fixture (`s ≈ λ ≈ 0`) for different reasons, and T3's pin
says exactly that. The kink measure AT THE DRIVER LEVEL is REGISTERED as a
possible third field for M7 if a heuristic wants the SSN's own reading.
What the number means: with `max(1, ‖λ‖∞)` scaling, a row at `λ = 10` reads
"weak" beside a row at `5e7` (probe D's ill-scaled family does exactly that)
— acceptable for telemetry, stated in the doc. Bound sides: rows only in
W4, bounds registered.

(c) **The row-kind census ("constraint tags")** — **AMENDED at the T2 ledger
(tycho-sqp pre-read, settler-adopted, 2026-09-04):** the SQP model contract
(`NlpModel`, `include/hven/model/nlp_model.h:70-173`) is the Level-1 SPLIT form —
`eval_ce` (= 0), `eval_ci` (≤ 0), bounds on VARIABLES only — so a five-kind ROW
census cannot be derived and is NOT emitted. `sqp.solve.begin` carries `me`/`mi`
and a five-way VARIABLE-bound census (free / lower_only / upper_only / ranged /
fixed); T3's per-major census is active ROWS + active bound SIDES (lower /
upper). The five-row-kind census below is REGISTERED for the M7 model-contract
work; the paragraph is kept for what it says about the Level-2 contract.
The model at that level already declares
`NLPRowKind` per row (`nlp_problem_model.h:39-46`: Equality, UpperBounded,
LowerBounded, Range, Free). `sqp.solve.begin` carries the five counts;
`sqp.major` carries the active count per kind (`active_upper`,
`active_lower`, `active_range_lower`, `active_range_upper`). Linear-vs-
nonlinear is NOT declared by the model contract (VERIFIED: `NLPRowKind` is
the five kinds and nothing under `include/hven/model/` carries a linearity
notion) — REGISTERED for M7, not invented here.

(d) **Inertia / conditioning evidence** the factorizations already produce:
NOT new fields — the IPQP stream has them (`inertia`, `perturbed`, `rho`);
the walk/SSN row gets `qp_factorizations` already. W4 adds nothing here;
the doc lists where each lives.
