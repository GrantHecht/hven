# U0 design note — the unified flag set, the re-derivation protocol, the CI flag posture

> Phase-C task U0 (`2026-08-15-m3-phase-c-plan.md` §6). This is the one-page
> design deliverable T0's dissolution folded into U0: the flag set, the
> re-derivation protocol, the delta-report bar, and the CI flag posture the
> S3 ruling made a hard requirement. Committed with the flags commit.

## 1. The unified flag set

One regime, already assembled in `cmake/hven_compile_options.cmake` and already
applied to `hven`, `hven_tests`, `hven_interior_tests`,
`hven_fault_injection_tests`, and every golden-rig target. U0 extends exactly
that `${COMPILE_FLAGS}` list to the last holdouts — `hven_sqp_tests` and the
five `bench/` targets — and changes no flag value. On Linux/clang that regime
is, concretely:

- common (both configs): `-pthread`, `-mllvm -inline-threshold=225`,
  `-fopenmp=libiomp5`;
- Release only: `-O3 -march=native -mtune=native -ffast-math
  -fno-finite-math-only -fomit-frame-pointer -fno-stack-protector
  -fno-asynchronous-unwind-tables` (HVEN_FP_MODE=SAFER_FAST);
- Debug only: `-g -ggdb3`.

Two consequences the re-derivation leans on: **Debug floating-point arithmetic
does not move** (every FP-relevant flag rides a Release-only generator
expression; `-inline-threshold` is codegen-shaping, FP-neutral at `-O0`), so a
pin that held in both configs and moves now splits per config with the Debug
side keeping its old value; and **the golden rig does not move at all** — it
was already compiled under this regime, which is also why its float rows carry
machine-context gates. The two comment blocks that declared the old boundary
(`src/CMakeLists.txt:11-29`, `tests/sqp/CMakeLists.txt:10-25`) are deleted by
the same commit; their deadline question ("no later than the phase-C TU
split") is answered here, "yes". `src/kkt/kkt_calls.cpp`'s bespoke FP-freedom
argument stays in the file as a historical record — it argued admission into a
regime boundary that no longer exists, and it remains true.

## 2. The CI flag posture (hard requirement, S3 ruling rider)

**Decision: the default regime keeps `-march=native`; CI lanes pin a fixed ISA
baseline per lane through a new `HVEN_SIMD_ARCH` cache variable.**
`HVEN_SIMD_ARCH=native` (the default, and the local/derivation regime) keeps
today's flags exactly; ci.yml passes `x86-64-v3` on the Linux and Windows
lanes (`-march=x86-64-v3`, no `-mtune`) and `apple-m1` on the macOS lane
(`-mcpu=apple-m1`, the wheel path's own Apple baseline).

Why this option and not the others the L-1 register left open:

- **`native` on the lanes is a pool lottery by construction.** The GitHub
  runner pool spans microarchitectures (including AVX-512-capable ones the
  local Zen 3 reference machine does not have); with the engine's FP paths now
  compiled `-ffast-math -march=native` in every asserting binary, per-runner
  codegen would make counter and float pins assert against whichever
  arithmetic the scheduler drew. L-1's four occurrences happened under
  byte-identical objects; `native` would add a second, larger variance source
  on top.
- **Runner-class pinning (labels) was the rejected alternative** — GitHub's
  hosted-runner labels do not pin microarchitecture (only image/size), so the
  "pin the runner" half of the register's open question is not actually
  purchasable on hosted runners; a fixed `-march` is.
- **A fixed baseline makes each lane ONE defined arithmetic.** A pin that
  disagrees on a pinned-ISA lane is then a stable, reproducible, derivable
  finding — re-derivable FROM the lane with run IDs and a two-run bar —
  instead of an intermittent flake. The residual within-lane variance is MKL
  kernel dispatch (the L-1 class), which is unchanged by this event, still
  OPEN, and still handled by rerun-plus-exoneration.
- The local reference machine (Zen 3: AVX2/FMA, no AVX-512) and `x86-64-v3`
  share vector width and FMA, so locally re-derived pins are *expected* to
  hold on the x86 lanes; where the U0 push proves otherwise, the disagreeing
  pin is adjudicated per-lane from lane evidence (never by widening a
  tolerance), and Accelerate-side values follow §6(c)4 into the divergence
  register. `wall-clock` asserts nothing on any lane, unchanged.

This changes lane FLAGS only; it is within U0's "flags only" bar, which is
about code motion.

## 3. The re-derivation protocol (the (b) package, operationally)

1. **Old-world capture first**: P-BENCH old arm at `8e2cbd0` (B2's 17-cell
   `--engine ssn` wall set × 4 reps + `bench_scale --self-check`, strictly
   serial, alone, `MKL_NUM_THREADS=1`), from a clean scratch build, before the
   flags commit exists.
2. **Flags commit** (zero code motion; this note rides with it).
3. **Suite re-derivation**: Release suite run twice fresh; every moved pin
   re-derived only from two agreeing fresh observations; Debug run to prove
   the no-movement expectation; cross-config splits use build-config pinning,
   never tolerance widening; status/verdict pins that move HALT the event;
   zero-pins that go nonzero are delta-report findings, not auto-pins. The
   frozen-artifact live-comparison tests are dispositioned per §6(b)5.
4. **Census**: two full-57 runs under `scripts/run_walk_census.sh`'s ratified
   parallel-tiered protocol, back-to-back, each alone on the machine, both
   tiered from the OLD baseline of record so the two runs share one fixed
   schedule; the NEW baseline is the two-run byte-agreement on the 13 asserted
   columns; disagreements go through the serial-confirm rule before any
   conclusion. New baseline lands as a NEW dated directory with an hven-native
   provenance header; the old artifacts freeze untouched; the CMake define
   repoints; every consumer test is enumerated and green in the same commit.
5. **P-WSB twice, P-BENCH new arm once** (same protocol as the old arm,
   identical machine conditions), then the delta report.

## 4. The delta-report bar

The event is accepted only through the reviewer + owner gate, on a committed
report carrying, at minimum: per-cell counter deltas for all 57 cells; every
status flip enumerated with its adjudication (a solved cell that stopped
solving halts the event before any report is written); the old-vs-new
KKT-residual distribution comparison with a flag-plausibility judgment;
battery counter deltas; the per-pin plausibility table for knife-edge and
zero pins; the P-BENCH old-vs-new verdict on Grant's "without sacrificing
performance"; and the CI run IDs for the three lanes on the landed unit.
Wall-clock from the census stays informational; the P-BENCH figures are the
only quotable timings and were produced serialized.
